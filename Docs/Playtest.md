# 웹 플레이 시험 (클라우드가 대신 해 보기)

사람이 로컬에서 직접 해 보며 보던 확인을 클라우드 세션이 먼저 한다(사용자 요청, 2026-11-04: "내가 테스트 요청하면 원래 로컬에서 내가 확인해야 하는 부분을 최대한 너가 테스트"). 클라우드 컨테이너의 헤드리스 Chromium으로 GitHub Pages의 웹 데모를 띄우고, 실제 키보드·마우스와 터치로 조작하고, 화면을 찍어 클라우드가 본다. Unity가 없어도 된다. WebGL은 SwiftShader(소프트웨어)로 그려서 초당 20프레임쯤 나온다.

## 돌리는 법

```
# 배포된 웹 데모로 지금 바로
node DevTools/WebPlaytest/playtest.js

# 방금 푸시한 것이 배포될 때까지(웹 데모 빌드는 15분쯤) 기다렸다가
node DevTools/WebPlaytest/playtest.js --wait

# 화면 하나만: pc, phone(휴대폰 세로 390×844), phone-wide(가로 844×390)
node DevTools/WebPlaytest/playtest.js --profiles phone

# 전체 점검: LOCAL_TASKS.md의 사람 확인을 차례로(30~40분)
node DevTools/WebPlaytest/sweep.js --wait

# 전체 점검의 일부만
node DevTools/WebPlaytest/sweep.js --only menu,npc,touch
```

**언제 무엇을 돌리나**(사용자 결정, 2026-11-09): 전체 점검은 사람이 요청할 때만. 평소 배포 뒤에는 그 커밋이 넣거나 바꾼 기능의 구역만 `--only`로 돌리고, 그 구역의 실패와 사진만 본다. 새 기능에 맞는 구역이 없으면 구역을 더한다.

전체 점검(`sweep.js`)의 부분: `menu`(메뉴 단추, 설정, 메뉴에는 클래스 단추가 없고 "게임 안에서 고른다", 키 바꾸기, 온라인, 진짜 클릭으로 시작한 뒤 첫 Tab), `time`(메뉴의 [하루 길이], 40분 월드의 시계 빠르기), `basics`(첫 화면, 퀵슬롯, 지도, 캐기, 목표, 놓기, 제작과 [만들 수 있는 것만], 상자, [상자에 넣기]와 잠금, 횃불), `bag`(드랍, 가방 격자에서 칸 고르기, 레벨 제한, 장착, [정렬], 룬, 버리기, 회복, 쓰러짐), `combat`(슬라임, 몬스터 열세 종류, 활·지팡이, 스킬 넷, 원소), `bosses`(보스 넷의 등장·페이즈·처치·드랍, 아레나를 떠나면 되돌아감), `world`(생물군계 다섯, 용암, 곡괭이 단계, 시간대의 빛), `farm`(심기, 물, 밭, 비료, 생물군계 작물, 스프링클러, 거두기), `life`(낚시 게이지, 술통, 닭장, 통발, 침대와 잠, 귀환), `npc`(상인의 사기·팔기·하루 한도·선물·부탁, 목표 목록의 부탁, [이야기] 1단계, [일지]·[캐릭터] 탭, 연금술사, 대장장이, 어부), `factory`(채굴기에서 상자까지, 전력, 기계 끄기, 거름망, 전기로, 조립기, 생산 통계), `gear`(모루, 특성, [스킬] 탭의 배우기·올리기·레벨 제한·되돌리기·[변형](결정 끼우고 빼기), 칸 순서, 클래스 바꾸기), `skills`(궁수·소환사·폭풍술사의 스킬 여섯을 하나씩 쓰고 사진, 스킬 아이콘), `base`(돌·벽돌·빛 바닥, 탁자, 깃발, 문 달린 벽을 지나가기), `save`(나갔다 들어오기, 새로 고침, 내보내기와 다른 브라우저로 가져오기), `deploysave`(돌릴 때마다 남겨 두는 브라우저 프로필 `out/profile-deploy`에 캐릭터를 남기고, 다음 배포에서 돌리면 그 레벨과 가방이 그대로인지 본다), `layout`(800×600, 375×812, 740×360의 메뉴·게임·가방·보스·지도), `touch`(휴대폰 세로·가로에서 탭으로 지도, 퀵슬롯, 물약, 가방, 기계 끄기, 스킬, 손가락으로 목록 끌기). 결과는 `DevTools/WebPlaytest/out/sweep/`.

결과는 `DevTools/WebPlaytest/out/`에 사진(`<화면>-<장면>.png`)과 `report.md`(확인 항목마다 통과·실패, 브라우저가 본 에러)로 남는다(커밋하지 않는다). 클라우드는 사진을 열어 보고, 사람에게는 사진과 숫자로 알 수 없는 것만 맡긴다.

## 무엇을 해 보는지

- **PC 1280×720, 키보드·마우스**: 메뉴, 혼자 하기, D로 걷기, Q 스킬과 마나, 마나 물약, 슬라임에 마우스를 누르고 있기(연타 사진 넷), Tab 가방, 세트를 입은 가방, 새 기계, 빛 구멍과 채광창(아침·저녁·보름달 밤), 장날, 폭풍·안개·비, 기지 방어, 공허 균열
- **휴대폰 세로·가로, 터치**: 탭하면 터치 화면이 되는지, 왼쪽 스틱을 끌어 걷기, 스킬 단추, 공격 스틱, 미니맵 아래 [가방] 단추, 기계 장면
- 확인마다 게임의 상태(위치, 마나, 맞은 몬스터 수, 기계의 전력, 날씨·행사, 방어·균열)를 읽어 통과·실패를 적는다. 브라우저 콘솔의 에러와 예외는 모두 모은다

## 처음 10분과 처음 한 시간 (2026-11-09)

`sweep.js --only first`: 새 캐릭터가 목표 안내만 보고 목표 1~6을 해 본다. 돌 모으기, 작업대, 횃불, 돌 바닥, 구리 광석, 구리 장비 하나다. 손은 봇 자신의 것이다(키, 가방 단추, 벽 쪽으로 공격). `give`·`build`는 쓰지 않는다. 화면이 자리를 알려 주지 않는 곳(다음 구리 광맥, 작업대로 돌아가기)만 `goto`로 옮기고 보고에 적는다. 봇은 둘레 벽을 파 작은 방을 만들고, 놓을 수 없으면 다른 빈 쪽으로 다시 해 본다. 목표마다 걸린 시간과 막힌 곳이 `report.md`에 남는다.

`sweep.js --only firstphone`(2026-11-09): 같은 봇을 휴대폰 세로(390×844) 터치로 돌린다. 걷기는 화면 왼쪽 절반을 끌고(이동 스틱), 캐기는 오른쪽 절반을 벽 쪽으로 끌고 있고(공격 스틱), 퀵슬롯·가방·[놓기]는 탭한다.

`sweep.js --only hour`(2026-11-09): 처음 10분 뒤로 목표 7~15를 이어서 한다. 버섯 심기, 호미로 밭 갈기, 낚싯대로 낚시, 상인에게 팔기, 화로, 채굴 기술 2, 동굴 수호자, 침대, 레벨 5. 싸움은 가장 가까운 몬스터·보스 쪽으로 걷다가 붙으면 그쪽으로 공격하고, 생명력이 40% 아래면 물약을 마시고, 떨어진 것을 밟아 줍는다. 보스에게 세 번 쓰러지면 그만둔다. 상태 보고의 `foe`, `bossAt`, `lootAt`(가장 가까운 몬스터·깨어난 보스·떨어진 것이 플레이어에게서 얼마나 떨어졌는지)을 쓴다. 상태 보고의 `music`은 지금 곡(`tune_sand_battle`, `boss_antlion_2` 따위)이다. `veinAt`은 미니맵이 가리키는 가장 가까운 구리 광맥(16칸 안)이고, 봇은 다음 광맥으로 옮겨지는 대신 그쪽으로 파 들어간다. 처음 한 시간 봇은 2026-11-09부터 목표 16(레벨 5)까지 간다(동굴 수호자 앞에 "레벨 3 되기").

### 첫 1시간 봇: 멈춘 자리와 남은 문제 (2026-11-10)

사람 결정(2026-11-10): 봇을 고치고 다시 돌리는 일이 토큰을 많이 써서, 여기서 멈추고 요청이 있으면 별도 세션에서 이어 간다. 월드가 판마다 달라 막히는 곳도 판마다 다르다. 다섯 판의 결과(`node DevTools/WebPlaytest/sweep.js --only hour`):

- 가장 멀리 간 판: 목표 1~15(동굴 수호자 79초, 쓰러짐 0번, 레벨 6)까지 이뤘고 목표 16 침대에서 멈췄다(슬라임 젤 부족)
- 고친 것: 채굴 기술 단계에서 마을 광장 밖으로 걸어 나가기(벽 0번 → 237번), 화로·침대 재료를 모자라면 더 모으기, 놓기 전에 쓰러졌으면 일어나기, 사냥 중 길·부두·선로 걷기, 40초 동안 몬스터가 안 보이면 `goto monster`(점검 장면에 더한 명령), 수호자 전 레벨 5까지 사냥
- 남은 문제(다음 세션에서 볼 것):
  1. **사냥에서 몬스터를 거의 못 만난다**: 판마다 "사냥 0마리". 마지막 판(66b9100)에서도 0마리였고 보고서에 `goto monster`로 옮겨졌다는 줄이 없다. `hunt()`가 그 가지에 닿지 않는 까닭부터 본다(`sweep.js`의 `const hunt`). 시험으로 재 보면 시작 지점 20칸 안의 몬스터는 장소가 있든 없든 평균 0~1마리, 35칸 안은 5~6마리다
  2. **첫 돌 10개**: 마지막 판은 131초 안에 돌 10개를 못 모아 목표 2부터 멈췄다(마을 광장에서 바위를 못 찾은 듯). `mine()`의 광장 밖으로 걸어 나가기가 첫 단계에서도 듣는지 본다
  3. **수호자를 낮은 레벨로**: 레벨 3~4에서는 5~8번 쓰러지고, 레벨 6 이상이면 잡는다. 1번이 풀려야 레벨을 올리고 간다
  4. **침대 젤**: 슬라임 젤 3이 드는데 사냥이 안 되면 모이지 않는다(1번과 같은 뿌리)
- 목표는 차례로 이뤄야 해서, 하나가 막히면 그 뒤 목표가 모두 실패로 나온다. 보고서의 "N초 목표 … 못 이룸 → 지금 목표 M"에서 처음 막힌 곳을 찾는다

## 게임 쪽 원격 조종 (`Client/Playtest.cs`)

페이지가 `unityInstance.SendMessage("Game", "Playtest", "<명령; 명령>")`을 부르면 혼자 하기에서만 듣는다(다른 사람이 있는 게임에서는 듣지 않는다). 명령마다 콘솔에 `[playtest] ...`로 답한다.

| 명령 | 하는 일 |
|---|---|
| `solo` | "playtest"라는 새 월드와 캐릭터로 혼자 하기를 시작한다 |
| `scene combo\|machines\|defense\|rift\|skylight\|set` | PlayMode 장면(`FeatureTests`)처럼 둘레를 꾸민다 |
| `clock <날> <시>`, `weather clear\|rain\|storm\|fog` | 시계를 옮긴다 |
| `give <재료> <개수>`, `potion <소모품> <개수>`, `drink <소모품>`, `mana <양>` | 가방과 마나 |
| `spawn <몬스터> <dx> <dy> [생명력]` | 곁에 몬스터를 둔다 |
| `attack on\|off [x y]`, `skill <칸>`, `touch on\|off`, `bag on\|off\|<탭 이름>` | 조작. `bag 스킬`처럼 탭 이름을 주면 그 탭으로 가방을 연다 |
| `hearts <사람> <호감>` | 그 사람(merchant, blacksmith, fisher)과 그만큼 호감 |
| `classes <id,id> [순서]` | 작업대와 레벨의 클래스 칸 없이 바로 그 클래스로(순서: 칸마다 클래스 스킬 목록의 몇 번째). 새 캐릭터는 클래스가 없어서(2026-11-09) `startSolo`가 안내 봇이 아니면 `classes warrior,fire_mage`를 보낸다 |
| `learn <스킬>`, `teach [단계]` | 포인트로 스킬 하나 배우기(단추와 같은 규칙), 클래스의 모든 스킬을 그 단계로 가르치기(포인트 없이) |
| `report` | 상태 한 줄(JSON) |
| `solo <이름> keep` | 저장본을 지우지 않고 이어서 시작한다 |
| `probe on`, `buttons` | 마지막 프레임에 그린 단추마다 글자, 줄(앞에 쓴 이름), 화면 위치(점), 눌리는지, 목록에서 보이는지(JSON). 스킬 칸·물약·퀵슬롯도 `skill N`, `potion`, `quick N`으로 |
| `texts` | HUD 줄(경험치 막대 글자, 상태 상자의 줄, 미니맵 아래 글자, 목표 목록 "목표 1/44: 돌 10개 모으기 (0/10) 보상: …"), 왼쪽 아래 줄(획득·알림), 가운데 배너, 떠 있는 글, 메뉴의 알림 줄(JSON) |
| `goto spawn\|<dx> <dy>\|boss <id>\|biome <이름>\|tile <칸>\|near <칸>` | 옮긴다. `near`는 그 칸 곁에 서서 바라본다 |
| `build <칸> <dx> <dy> [방향]`, `fill <dx> <dy> <재료> <개수>`, `look <dx> <dy>` | 칸을 짓고, 기계·상자에 넣고, 칸·기계·상자·작물을 읽는다 |
| `drop item <베이스> [등급] [소켓]\|rune\|potion <id>\|material <id>`, `inventory` | 발밑에 떨어뜨리고, 가방을 읽는다 |
| `speed <틱>` | 혼자 하기 월드를 한 걸음에 그만큼 돌린다(0은 멈춤, 최대 60) |
| `hurt <양>`, `boss <id> hurt <비율>`, `xp <양>`, `heal`, `clear`, `equip <베이스...>`, `face <x> <y>\|off` | 싸움과 같은 길로 다치고, 레벨을 올리고, 바라본다 |

단추는 모두 `Ui.Button`·`Ui.LayoutButton`·`Ui.Toolbar`를 거친다(`Ui.cs`). 시험이 `probe on`을 켜 두면 그린 단추를 기억하고, 시험 도구(`lib.js`의 `press`)는 그 자리를 진짜 클릭이나 탭으로 누른다. 목록 밖으로 스크롤된 단추는 마우스 휠로 찾아간다. 새 단추를 만들 때도 이 셋을 쓴다.

웹 페이지(`Assets/WebGLTemplates/Fit/index.html`)는 `window.unityInstance`를 열어 두고, 웹 데모 워크플로는 배포에 `version.txt`(커밋)를 넣어 `--wait`가 기다릴 수 있게 한다.

## 사진으로 알 수 없는 것

손맛(연타의 리듬, 히트 스톱이 거슬리지 않는지), 소리, 실제 휴대폰의 손가락 감각과 성능, 오래 해 보는 재미. 이것만 사람에게 묻는다. 로컬의 Unity 에디터 시험(명령 한 줄, 감시 스크립트)은 그대로 둔다: 에디터에서만 드러나는 문제(임포트, 에셋, `.meta`)를 잡는다.
