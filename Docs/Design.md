# pray-to 설계 문서

초안이다. 정해진 것과 아직 열린 질문을 같이 적는다. 방향이 바뀌면 코드보다 이 문서를 먼저 고친다.

## 어떤 게임인가

코어키퍼 같은 탑뷰 2D 액션·생존·크래프팅 게임이다. 혼자 또는 친구들과 협동으로 지하 세계를 파고들며 보스를 잡고, 그 재료로 다음 단계 장비를 만든다. 전투를 하지 않는 시간에도 농사와 자동화로 꾸준히 성장할 수 있다.

## 핵심 기둥

| 기둥 | 목표 |
|---|---|
| 계단식 성장 | 보스 처치 → 새 재료 → 새 장비 티어 → 새 지역. 단계가 오를 때마다 확실히 체감되도록 수치가 계단 모양으로 오른다 |
| 클래스 조합 | Craft to Exile 2처럼 여러 클래스를 섞는다. 스킬에 태그(화염, 투사체, 소환 등)를 달고 장비·패시브가 태그를 강화해서 조합마다 다른 빌드가 나온다 |
| 보스전 | 페이즈 전환, 예고(텔레그래프)가 있는 패턴, 협동할 때 역할이 갈리는 기믹 |
| 루팅 | 같은 아이템도 접두사·접미사와 룬 소켓으로 매번 다르다. 희귀도가 높을수록 접두사가 많고 강하다 |
| 내실 | 농사와 자동화(채굴·제련·운반). 전투 없이도 시간을 들이면 좋은 보상을 얻는다. 전투와의 시간당 가치를 시뮬레이션으로 비교해 맞춘다 |

## 기술 원칙

### 1. Core가 게임이다

게임 규칙과 시뮬레이션은 전부 `Game.Core`에 순수 C#으로 둔다. 이동·충돌, 전투, 적 AI, 아이템 생성, 인벤토리, 제작, 농사, 자동화가 다 여기 들어간다. Unity는 화면, 입력, 소리, 네트워크 전송만 맡는다.

- 클라우드 세션이 Unity 없이 만들고 테스트할 수 있다
- 호스트 시뮬레이션을 봇으로 돌려 밸런스를 잰다 (`DevTools/CoreSandbox`)
- 충돌은 Unity Physics2D 대신 타일 격자와 원 판정으로 Core에서 직접 한다. 탑뷰 타일 월드라 이걸로 충분하고, 그래야 위 두 가지가 가능하다

### 2. 에디터에서 손으로 만드는 콘텐츠를 두지 않는다

- 월드: 시드 기반 절차 생성
- 아이템·접두사·룬·몬스터·보스·작물·레시피: 데이터 시트에서 에디터 메뉴 한 번으로 에셋을 만든다
- 씬: 시작 씬 하나에 나머지는 코드로 구성

이렇게 해야 대부분의 작업이 클라우드에서 끝나고, 로컬 Unity 작업은 명령 한 줄(`DevTools/Local/setup.ps1`)과 직접 플레이해 보는 확인으로 줄어든다. 명령 한 줄은 배치 모드로 프로젝트 설정과 씬 생성, EditMode·PlayMode 테스트를 하고 결과를 `LOCAL_TASKS.md`에 적는다.

### 3. 멀티플레이는 호스트 권한

- 플레이어 한 명이 호스트(listen server)가 되어 Core 시뮬레이션을 돌린다. 나머지는 입력과 요청을 보내고 결과를 받는다
- 싱글플레이는 "혼자 연 호스트"다. 같은 코드 경로를 쓰므로 멀티 버그가 싱글에서도 드러난다
- 내 캐릭터 이동만 클라이언트가 먼저 움직이고(같은 Core 이동 코드로) 호스트가 받아들인다. 협동 게임이라 치팅 방지보다 반응성을 우선한다
- 적, 피해, 드랍, 인벤토리, 월드 변경(채굴·설치)은 호스트만 결정한다. 바뀐 칸은 호스트가 모두에게 보낸다
- 전송은 Netcode for GameObjects와 Unity Transport를 쓴다. Core는 네트워크 라이브러리를 모르고 메시지만 주고받는다
- 실제 메시지와 이동 보정 방식은 `Docs/Multiplayer.md`에 있다

### 4. 결정적 난수와 고정 틱

- Core는 `System.Random` 대신 `GameRandom`(PCG32)을 쓴다. 같은 시드면 .NET 테스트와 Unity(Mono·IL2CPP·Web)가 같은 수를 낸다. 덕분에 월드 시드만 보내면 클라이언트도 같은 지형을 만들 수 있고, 버그와 밸런스 결과를 시드로 재현할 수 있다
- 지형 생성은 정수 연산 위주로 짠다. 부동소수점 연산 결과는 플랫폼마다 미세하게 달라질 수 있다
- 시각(`DateTime.Now` 등)은 Core 안에서 읽지 않고 밖에서 넘겨받는다
- 호스트 시뮬레이션은 초당 30틱으로 돈다. 스냅샷은 2틱마다 보낸다. 농사·자동화도 틱 단위라서 접속하지 않은 동안의 진행을 몰아서 계산하기 쉽다

### 5. 시뮬레이션으로 밸런싱한다

`CoreSandbox`에서 다음을 숫자로 확인한다.

- 드랍 1만 회의 희귀도·접두사 분포
- 봇 파티 대 보스의 승률과 소요 시간
- "전투 1시간"과 "농사·자동화 1시간"의 보상 비교

### 6. 웹 데모는 Unity Web 빌드로 만든다

GitHub Actions(GameCI)로 푸시마다 빌드해 GitHub Pages에 올린다(저장소를 공개로 전환하기로 했다). 터치 조작, 게임에 넣은 한글 글꼴, 화면 밀도에 맞춘 UI 크기, Pages에서 도는 압축 설정을 갖췄다. 브라우저는 호스트가 될 수 없으므로 웹에서는 혼자 하기만 된다. 자세한 건 `Docs/WebDemo.md`. CI용 Unity 라이선스, 공개 전환, Pages 설정은 사람이 해야 한다(`LOCAL_TASKS.md`의 "웹 데모용").

### 7. PC와 모바일 크로스 플랫폼

PC(키보드·마우스)와 모바일(터치)에서 같은 게임을 한다(사용자 결정, 2026-10-29).

- 새 기능은 처음부터 두 입력 모두로 쓸 수 있게 만든다. 키 하나에 붙인 기능은 터치 버튼도 같이 만들고, 마우스로 겨누는 것은 터치 스틱으로도 겨눌 수 있게 한다
- UI는 휴대폰 가로·세로 화면과 작은 PC 창(800×600쯤)에 모두 들어가야 한다. 크기는 `Ui`의 점 단위로 잡고, 손가락으로 누를 버튼은 40점 이상으로 만든다
- 마우스 올리기(hover)에만 기대는 정보는 터치에서 볼 방법(누르고 있기 등)도 둔다
- 지금 모바일은 웹 데모(브라우저)로 확인한다. 앱으로 낼지는 나중에 정한다

## 화면과 조작

### 지도

- 오른쪽 위에 미니맵이 늘 있다. 내 주변 40×40칸을 보여 준다. 미니맵을 탭하거나 클릭하면 동굴 전체 지도가 크게 열리고, 아무 데나 다시 탭하거나 클릭하면 닫힌다. PC는 M으로 열고 닫고, Esc로도 닫는다
- **가 본 곳만 보인다.** 내가 지나간 자리에서 8칸(화면에 보이는 만큼) 안의 바닥과 벽이 지도에 채워진다. 동굴을 파고드는 맛을 지도가 거들게 하려는 것이다
- 표시: 바닥, 벽, 보스 아레나 바닥(붉은색), 나(흰 점), 다른 플레이어(파란 점), 보스 아레나(빨간 원). 아레나는 HUD가 이미 방향과 거리를 알려 주므로 가 보지 않았어도 표시한다. 몬스터와 바닥 아이템은 지도에 넣지 않는다(화면에서 본다)
- 지도가 크게 열려 있는 동안 공격은 막고, 터치는 이동·공격으로 넘기지 않는다. 다른 플레이어와 함께하는 게임이라 시간은 멈추지 않는다
- 가 본 곳 기록은 화면 쪽(`MapView`)에만 있고 세션이 끝나면 사라진다. 저장이 생기면 캐릭터와 함께 저장할지 정한다(열린 질문)

### 터치

- 왼쪽 절반: 이동 스틱. 누른 자리에 생기고, 덜 끌면 천천히 걷는다
- 오른쪽 절반: 공격 스틱. 누르고 있는 동안 계속 휘두르고, 끄는 방향을 바라본다. 거의 끌지 않으면 걷는 방향으로, 서 있으면 바라보던 방향 그대로 휘두른다
- 미니맵 아래 [가방]·[나가기] 버튼. 버튼과 창 위에서 시작한 터치는 스틱으로 치지 않는다
- 오른쪽 아래 구석에 스킬 버튼(2×2). 스틱을 잡은 채 다른 손가락으로 눌러도 된다(`Docs/Classes.md`)
- PC는 키보드와 마우스(마우스 쪽을 바라본다) 그대로다. 스킬은 Q, E, R, F

## 열린 질문

- 최대 협동 인원 (코어키퍼는 8명). 지금은 4명으로 두었다(`HostConfig.MaxPlayers`)
- 인터넷 너머 접속: Unity Relay, Steam 네트워킹 중 무엇을 쓸지
- 아트 스타일과 해상도: 픽셀아트, 타일 16px(PPU 16)로 임시로 정했다(2026-10-30, 사람이 도트풍을 요청). 화면 크기와 상관없이 픽셀이 고르게 보이는 카메라 설정, 캐릭터를 더 크게 할지는 아직이다(`Docs/ArtPipeline.md`)
- 월드 크기: 고정인지 무한인지
- 가 본 곳 지도: 세션이 끝나면 사라진다. 캐릭터에 붙일지(협동하면 각자 다른 지도), 월드에 붙일지(모두가 같은 지도). 저장(`Docs/Saving.md`)에는 아직 넣지 않았다
