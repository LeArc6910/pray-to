# pray-to 설계 문서

초안이다. 정해진 것과 아직 열린 질문을 같이 적는다. 방향이 바뀌면 코드보다 이 문서를 먼저 고친다.

## 어떤 게임인가

코어키퍼 같은 탑뷰 2D 액션·생존·크래프팅 게임이다. 혼자 또는 친구들과 협동으로 지하 세계를 파고들며 보스를 잡고, 그 재료로 다음 단계 장비를 만든다. 전투를 하지 않는 시간에도 농사와 자동화로 꾸준히 성장할 수 있다.

**플레이 경험의 기준**(사용자 결정, 2026-11-03). 어느 쪽도 그대로 베끼지 않고, 하는 맛을 비슷하게 가져간다.

- **전투와 성장**: 마인크래프트 모드팩 Craft to Exile 2(Mine and Slash 중심)처럼 한다. 레벨을 올리고, 접사가 붙은 장비를 모으고 다듬는다. 여러 클래스를 섞어 빌드를 짜고, 갈수록 어려워지는 끝판 콘텐츠를 돈다
- **공장**: 팩토리오 정도의 깊이로 만든다. 여러 단계를 거치는 생산 사슬, 기계 사이의 비율 맞추기, 공장을 키워 생산량을 늘리는 재미가 있어야 한다
- **생활**: 농사, 낚시, 요리 같은 생활 콘텐츠는 스타듀밸리 정도로 충분히 깊게 즐길 수 있게 만든다(사용자 결정, 2026-11-03). 싸우지 않아도 오래 즐길 거리가 되어야 한다
- **공장과 사냥은 균형을 맞추되, 공장에 너무 기대게 하지 않는다**(사용자 결정, 2026-11-03)
  - 공장에서만 만들 수 있는 것은 없다. 공장이 만드는 것은 모두 사람이 손으로도 만들 수 있다
  - 공장은 사람이 여러 번 손을 써야 하는 일을 대신해 준다. 캐기, 녹이기, 같은 제작을 되풀이하기, 나르기 같은 것이다
  - 그래서 공장 없이도 끝까지 갈 수 있다. 공장을 키우면 같은 일에 드는 시간과 손이 줄어든다

**월드와 전투 다시 짜기**(사용자 결정, 2026-11-21). 사람 말: "지금 게임 플레이 방식이 너무 단조로워. 몹들은 너무 흩어져서 나와서 핵앤슬레시 하는 느낌도 안들고 그렇다고 일반 몹들이 하나하나 다크소울처럼 치명적이어서 피해 다녀야 하는 것도 아냐. 맵도 그저 크기만 늘렸을 뿐 내가 탐험한다는 느낌이 전혀 안들고 목적지로 걸어가야한다는 느낌밖에 안들어." 다섯 단계를 차례로 만든다. 설계와 숫자는 `Docs/WorldRework.md`, 몬스터별 패턴은 `Docs/MonsterPatterns.md`.

- **크기보다 밀도**: 지도는 1024칸 그대로 두고, 걸어서 15~30초마다 새것이 나오게 한다
- **지도의 뼈대**(1단계): 흩어진 바위 대신 방과 통로, 시야를 가리는 큰 벽 덩어리. 생물군계마다 지형이 다르다(버섯 숲은 미로, 얼음 동굴은 넓은 홀, 용암 지대는 용암 강과 다리). 방마다 역할(무리 방, 정예 야영지, 보물 방, 야영지, 자물쇠 방)이 있고, 특별한 방은 시트의 글자 그림 조각을 끼운다. 길은 고리가 된다
- **무리와 정예**(2단계): 몬스터는 방에서 4~8마리 무리로 나오고 함께 알아차린다. 길과 야영지는 비운다. 들판에도 정예(우두머리와 부하, 접사)가 있다
- **일반 몬스터의 패턴**(2b단계): 종마다 제 공격 수단 2~3개와 이펙트를 가진다. 보스의 공격 엔진과 전조 말 다섯을 함께 쓴다. 떼는 여럿이 약하게(소모전), 무거운 적과 정예는 크고 예고된 한 방(회피전)
- **탐험의 보상**(3단계): 야영지, 제단의 축복, 보물·숨은 방, 곡괭이 단계로 여는 자물쇠 방, 광차 지름길. 불빛과 연기처럼 멀리서 보이는 신호로 끈다
- **구르기와 완급**(4단계): 모든 클래스의 구르기(짧은 무적, PC 키와 휴대폰 단추), 싸움 뒤에 쉬게 하는 완급 감독, 화살표 대신 소문, 탐험에서 얻는 회복
- **인스턴스 던전**(5단계): 문으로 들어가는 5~15분짜리 따로 된 지도. 들어갈 때마다 방 조각과 개념 그래프로 새로 만든다. 같은 문으로 들어온 사람은 같은 던전에 있다. 지도 하나의 주머니 구역에 그려 호스트 시뮬레이션은 하나로 둔다
- 아래 "이야기와 장소"의 장소·길·웨이포인트는 그대로다. 길 위에 몬스터가 생기지 않는 것도 그대로다. 길의 모양(방 그래프를 따라가고 고리가 생긴다)과 안내의 정확도만 바뀐다
- 새 지형은 새로 만드는 월드부터다. 옛 월드는 옛 생성기(1판)로 그대로 연다(사람 결정 2026-11-21)

**이야기와 장소**(사용자 결정, 2026-11-10). 디아블로처럼 이야기를 따라 장소를 옮겨 가며 즐긴다.

- **줄거리의 뼈대**: 마왕군과의 전쟁에서 이긴 여왕과 용사가 있다. 그런데 사실 용사가 마왕을 숨겨 주고 있다. 사람이 이야기를 바꾸고 더할 예정이라 이야기는 코드가 아니라 시트(`story.csv`, `characters.csv`, `places.csv`)에 둔다(`Docs/Story.md`)
- **장소**: 왕국, 마을, 마족 둥지처럼 사람들이 모여 사는 곳을 지하 세계에 둔다. 시드로 만드는 동굴 안에 깎아 넣고, 장소마다 웨이포인트가 있어 한 번 가 본 웨이포인트끼리 순간이동한다
- **길**: 장소들은 포장된 길로 이어져 길만 따라가도 다음 장소에 닿는다. 길 위에는 몬스터가 생기지 않는다. 길을 벗어나 굴을 파고드는 것은 지금처럼 자유다
- **흐름**: 이야기 한 단계는 인물에게 말을 걸어 받는다. 장소에 닿기, 보스 쓰러뜨리기, 물건 가져가기를 하면 다음 단계로 간다. 목표 목록 맨 위에 지금 단계와 가야 할 곳이 나온다. 첫 장(왕도·동굴 수호자·용사의 오두막)과 한 번 가 본 곳은 방향·거리, 그 밖은 소문으로 방향과 생물군계만("북동쪽, 버섯 숲 어딘가", 150칸 안에 오거나 그쪽 이정표를 보면 "북동쪽"), 지도에는 옅은 원(2026-11-22, `Docs/WorldRework.md` 묶음 4c). 메뉴의 [길 안내: 화살표]면 예전처럼 늘 방향·거리
- **소문**(2026-11-22, 묶음 4c): 이야기의 인물은 평소 말에 이어 볼거리(야영지·제단·상자·숨은 방·금고·수레·끊긴 광차역·길잡이 돌·정예 야영지)나 오늘 떠돌이 상인이 있는 곳의 소문을 하나 들려준다(`characters.csv` `rumor`, `Docs/Story.md`). 들으면 지도에 옅은 원이 남는다. 쉬면 차오르는 회복은 8초 뒤 초당 1.5%로 줄여(예전 6초 뒤 3%) 야영지·제단·물약을 찾게 한다. 둘 다 기본으로 켜고 메뉴에서 예전처럼 바꾼다(사람 결정 2026-11-21)

## 핵심 기둥

| 기둥 | 목표 |
|---|---|
| 계단식 성장 | 보스 처치 → 새 재료 → 새 장비 티어 → 새 지역. 단계가 오를 때마다 확실히 체감되도록 수치가 계단 모양으로 오른다. 장비 단계는 앞 단계의 두 배쯤, 레벨은 열 레벨마다 한 번 크게 뛰고, 보스는 제 단계 장비로는 물약을 쓰며 잡되 한 단계 아래 장비로는 벽이 되게 맞춘다(2026-11-17, 숫자는 `Docs/Bosses.md`의 "계단식 성장") |
| 클래스 조합 | Craft to Exile 2처럼 여러 클래스를 섞는다. 스킬에 태그(화염, 투사체, 소환 등)를 달고 장비·패시브가 태그를 강화해서 조합마다 다른 빌드가 나온다 |
| 보스전 | 페이즈 전환, 예고(텔레그래프)가 있는 패턴, 협동할 때 역할이 갈리는 기믹 |
| 루팅 | 같은 아이템도 접두사·접미사와 룬 소켓으로 매번 다르다. 희귀도가 높을수록 접두사가 많고 강하다 |
| 이야기와 장소 | 인물에게 말을 걸어 이야기를 받고, 길을 따라 장소를 옮겨 간다. 장소마다 웨이포인트(2026-11-10, `Docs/Story.md`) |
| 내실 | 농사와 자동화(채굴·제련·운반). 전투 없이도 시간을 들이면 좋은 보상을 얻는다. 전투와의 시간당 가치를 시뮬레이션으로 비교해 맞춘다. 자동화는 팩토리오 정도의 생산 사슬까지 키운다(2026-11-03). 다만 공장에서만 나오는 것은 없고, 공장은 손으로 되풀이하던 일을 덜어 준다(위 "플레이 경험의 기준"). 지금은 광석→주괴→부품(톱니·구리선·회로)→기계로 이어지고, 전력망·조립기·물레방아·태양판·큰 제련로까지 있다(`Docs/Automation.md`) |

## 기술 원칙

### 1. Core가 게임이다

게임 규칙과 시뮬레이션은 전부 `Game.Core`에 순수 C#으로 둔다. 이동·충돌, 전투, 적 AI, 아이템 생성, 인벤토리, 제작, 농사, 자동화가 다 여기 들어간다. Unity는 화면, 입력, 소리, 네트워크 전송만 맡는다.

- 클라우드 세션이 Unity 없이 만들고 테스트할 수 있다
- 호스트 시뮬레이션을 봇으로 돌려 밸런스를 잰다 (`DevTools/CoreSandbox`)
- 충돌은 Unity Physics2D 대신 타일 격자와 원 판정으로 Core에서 직접 한다. 탑뷰 타일 월드라 이걸로 충분하고, 그래야 위 두 가지가 가능하다

### 2. 에디터에서 손으로 만드는 콘텐츠를 두지 않는다

- 월드: 시드 기반 절차 생성
- 아이템·접두사·룬·몬스터·보스·작물·레시피: 데이터 시트에서 에디터 메뉴 한 번으로 에셋을 만든다
- 씬: 시작 씬 하나에 나머지는 코드로 구성

이렇게 해야 대부분의 작업이 클라우드에서 끝나고, 로컬 Unity 작업은 명령 한 줄(`DevTools/Local/setup.ps1`)과 직접 플레이해 보는 확인으로 줄어든다. 명령 한 줄은 배치 모드로 프로젝트 설정과 씬 생성, EditMode·PlayMode 테스트를 하고 결과를 `LOCAL_TASKS.md`에 적는다. PlayMode의 장면 테스트(`FeatureTests`)는 호스트 월드를 직접 꾸며(기계, 방어, 균열, 날씨) 실제 화면으로 몇 초씩 그려 보고, 에러가 찍히면 실패한다. 손으로 해 보는 확인 전에 그리는 쪽의 오류를 먼저 잡는다. 감시 스크립트(`watch.ps1`)를 켜 두면 이 모두가 클라우드의 푸시마다 저절로 돌고, 장면의 화면 사진이 `local-screens` 브랜치로 올라와 클라우드가 본다(2026-11-04). 사람은 손맛, 소리, 실제 휴대폰처럼 사진으로 알 수 없는 것만 본다.

### 3. 멀티플레이는 호스트 권한

- 플레이어 한 명이 호스트(listen server)가 되어 Core 시뮬레이션을 돌린다. 나머지는 입력과 요청을 보내고 결과를 받는다
- 싱글플레이는 "혼자 연 호스트"다. 같은 코드 경로를 쓰므로 멀티 버그가 싱글에서도 드러난다
- 내 캐릭터 이동만 클라이언트가 먼저 움직이고(같은 Core 이동 코드로) 호스트가 받아들인다. 협동 게임이라 치팅 방지보다 반응성을 우선한다
- 적, 피해, 드랍, 인벤토리, 월드 변경(채굴·설치)은 호스트만 결정한다. 바뀐 칸은 호스트가 모두에게 보낸다
- 전송은 Netcode for GameObjects와 Unity Transport를 쓴다. Core는 네트워크 라이브러리를 모르고 메시지만 주고받는다
- 실제 메시지와 이동 보정 방식은 `Docs/Multiplayer.md`에 있다

### 4. 결정적 난수와 고정 틱

- Core는 `System.Random` 대신 `GameRandom`(PCG32)을 쓴다. 같은 시드면 .NET 테스트와 Unity(Mono·IL2CPP·Web)가 같은 수를 낸다. 덕분에 월드 시드만 보내면 클라이언트도 같은 지형을 만들 수 있고, 버그와 밸런스 결과를 시드로 재현할 수 있다
- 지형 생성은 정수 연산 위주로 짠다. 부동소수점 연산 결과는 플랫폼마다 미세하게 달라질 수 있다
- 시각(`DateTime.Now` 등)은 Core 안에서 읽지 않고 밖에서 넘겨받는다
- 호스트 시뮬레이션은 초당 30틱으로 돈다. 스냅샷은 2틱마다 보낸다. 농사·자동화도 틱 단위다. 월드를 닫아 둔 동안에는 아무것도 진행하지 않는다(`Docs/Time.md`)

### 5. 시뮬레이션으로 밸런싱한다

`CoreSandbox`에서 다음을 숫자로 확인한다.

- 드랍 1만 회의 희귀도·접두사 분포
- 봇 파티 대 보스의 승률과 소요 시간
- "전투 1시간"과 "농사·자동화 1시간"의 보상 비교

### 6. 웹 데모는 Unity Web 빌드로 만든다

GitHub Actions(GameCI)로 푸시마다 빌드해 GitHub Pages에 올린다(저장소를 공개로 전환하기로 했다). 터치 조작, 게임에 넣은 한글 글꼴, 화면 밀도에 맞춘 UI 크기, Pages에서 도는 압축 설정을 갖췄다. 브라우저는 연결을 받을 수 없어 LAN 호스트는 안 되지만, Unity Relay의 방 코드로 웹끼리, 웹과 PC가 함께 협동한다(2026-11-02, `Docs/Multiplayer.md`의 "온라인"). 자세한 건 `Docs/WebDemo.md`. CI용 Unity 라이선스, 공개 전환, Pages 설정은 사람이 해야 한다(`LOCAL_TASKS.md`의 "웹 데모용").

### 7. PC와 모바일 크로스 플랫폼

PC(키보드·마우스)와 모바일(터치)에서 같은 게임을 한다(사용자 결정, 2026-10-29).

- 새 기능은 처음부터 두 입력 모두로 쓸 수 있게 만든다. 키 하나에 붙인 기능은 터치 버튼도 같이 만들고, 마우스로 겨누는 것은 터치 스틱으로도 겨눌 수 있게 한다
- UI는 휴대폰 가로·세로 화면과 작은 PC 창(800×600쯤)에 모두 들어가야 한다. 크기는 `Ui`의 점 단위로 잡고, 손가락으로 누를 버튼은 40점 이상으로 만든다
- 마우스 올리기(hover)에만 기대는 정보는 터치에서 볼 방법(누르고 있기 등)도 둔다
- 지금 모바일은 웹 데모(브라우저)로 확인한다. 앱으로 낼지는 나중에 정한다

## 화면과 조작

### 지도

- 오른쪽 위에 미니맵이 늘 있다. 내 주변 40×40칸을 보여 준다. 미니맵을 탭하거나 클릭하면 동굴 전체 지도가 크게 열리고, 아무 데나 다시 탭하거나 클릭하면 닫힌다. PC는 M으로 열고 닫고, Esc로도 닫는다
- **가 본 곳만 보인다.** 내가 지나간 자리에서 8칸(화면에 보이는 만큼) 안의 바닥과 벽이 지도에 채워진다. 동굴을 파고드는 맛을 지도가 거들게 하려는 것이다
- 표시: 바닥, 벽, 보스 아레나 바닥(붉은색), 나(흰 점), 다른 플레이어(파란 점), 보스 아레나(빨간 원). 아레나는 가 보지 않았어도 표시한다(HUD의 방향 줄은 2026-11-08에 뺐다. 지도에서 본다). 몬스터와 바닥 아이템은 지도에 넣지 않는다(화면에서 본다)
- 소문 안내(2026-11-22, `Docs/WorldRework.md` 묶음 4c, 기본): 첫 보스의 아레나 말고는 본 적 없는 아레나, 가 본 적 없는 장소, 이야기가 이끄는 곳이 정확한 표시 대신 전체 지도의 옅은 원(반지름 40칸, 150칸 안이면 20칸, 가운데가 그것에서 비껴 있다)이다. 인물에게 들은 소문도 옅은 원으로 남는다. 메뉴의 [길 안내: 화살표]면 예전처럼 표시한다
- 가까운 광맥(2026-11-09): 둘레 16칸 안의 가장 가까운 구리·철 광맥을 그 광석 색의 깜박이는 고리로 표시한다. 가 보지 않았어도, 벽 너머여도 보인다(광부의 감). 처음 10분 점검에서 봇이 다음 구리 광맥을 찾지 못해 번번이 옮겨졌고, 안내도 모양만 알려 주고 자리는 알려 주지 않았다(`MapView.Sense`)
- 지도가 크게 열려 있는 동안 공격은 막고, 터치는 이동·공격으로 넘기지 않는다. 다른 플레이어와 함께하는 게임이라 시간은 멈추지 않는다
- 가 본 곳 기록은 캐릭터마다, 월드 시드마다 각자의 기기에 저장한다(2026-11-02, `Docs/Saving.md`). 협동하면 사람마다 지도가 다르다

### 터치

- 왼쪽 절반: 이동 스틱. 누른 자리에 생기고, 덜 끌면 천천히 걷는다
- 오른쪽 절반: 공격 스틱. 누르고 있는 동안 계속 휘두르고, 끄는 방향을 바라본다. 거의 끌지 않으면 걷는 방향으로, 서 있으면 바라보던 방향 그대로 휘두른다
- 미니맵 아래 [가방]·[나가기] 버튼. 버튼과 창 위에서 시작한 터치는 스틱으로 치지 않는다
- 오른쪽 아래 구석에 스킬 버튼(2×2). 스틱을 잡은 채 다른 손가락으로 눌러도 된다(`Docs/Classes.md`)
- PC는 키보드와 마우스(마우스 쪽을 바라본다) 그대로다. 스킬은 Q, E, R, F, 물약 C, 퀵슬롯 1~6, 가방 Tab, 지도 M, 기계 켜기/끄기 G이고, 메뉴의 [키 바꾸기]에서 바꿀 수 있다(이동 WASD·화살표, 공격 스페이스, Esc는 그대로). 바꾼 키는 기기에 기억되고 메뉴의 조작 안내와 스킬 칸 글자도 따라 바뀐다(2026-11-01)
