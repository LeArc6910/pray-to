# 크로스 플레이 준비 (2026-11-27)

PC·휴대폰·웹이 같은 방에서 함께 한다. 모두 Unity Relay(wss)로 이어지고 같은 방 코드로 만난다(`Docs/Multiplayer.md` 온라인). 이번에 맞춘 것:

## 지도 일치 (`Core/Net/MapPrint.cs`)

- 참가자는 시드로 지도를 직접 만든다. 생성기에 실수(float) 계산이 수십 줄 남아 있어 기기·컴파일러마다 한 칸이 어긋날 수 있다
- 호스트는 만든 그대로의 지도 지문(타일과 생물군계의 FNV-1a)을 환영 메시지에 싣는다. 참가자의 지문이 다르면 `MapRequest`를 보내고, 호스트는 지금 지도(타일·생물군계)를 줄 길이로 묶어(게임 지도 1024칸이 수백 KB) 48KB씩 `MapData`로 보낸다. 참가자는 받아 덮고 "이 기기의 지도가 호스트와 달라 호스트의 지도를 받았다" 띠를 한 번 보인다
- 방 그래프(방·통로·볼거리·사냥터)는 보내지 않는다: 타일이 어긋날 정도면 대개 같지만, 다르면 볼거리 표시가 어긋날 수 있다. 근본 해결은 생성기를 정수 계산으로 바꾸는 일(남은 일)

## 버전 정책

- 규칙·시트·메시지가 바뀌면 통신 버전(`Protocol.Version`)을 올린다. 같은 버전끼리만 함께 한다(기기는 상관없음)
- 다르면 참가가 거절되고 누가 업데이트할지 알려 준다: "내 게임을 업데이트하세요(웹은 새로고침, 앱은 새 버전 받기)" 또는 "호스트가 게임을 업데이트해야 합니다"(`Protocol.VersionRefusal`)
- 웹 데모는 main에 올릴 때마다 새 버전이 되므로, 앱과 함께 하려면 앱도 같은 커밋으로 빌드해야 한다

## 웹 호스트

- 브라우저는 숨긴 탭의 게임을 멈춘다(호스트가 멈추면 모두 멈춤). 웹으로 방을 열면 미니맵 아래에 "웹으로 연 방: 탭을 숨기면 멈춘다 · 오래 열 방은 앱으로"가 늘 보인다. 오래 열 방은 PC·휴대폰 앱으로 여는 것을 권한다

## 휴대폰 재접속

- 참가자가 호스트와 끊기면(휴대폰을 백그라운드로 보냈다가 돌아옴 등) 캐릭터를 저장하고 같은 방 코드로 2초 간격 세 번까지 다시 들어간다("연결이 끊어져 같은 방에 다시 잇는 중… (1/3)"). 다시 들어가면 횟수는 처음부터(`GameRoot.CrossPlay.cs`)
- 호스트가 휴대폰이면 백그라운드에서 방이 멈춘다(앱이 멈추므로): 호스트는 화면을 켜 둔다

## 사람이 할 일
