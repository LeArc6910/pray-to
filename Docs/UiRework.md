# UI 다시 짜기

설계 제안 문서다(2026-11-22). 사람이 [6절](#6-사람이-정할-것)의 것을 골랐고([사람이 정한 것](#사람이-정한-것-2026-11-22)), [5절](#5-만드는-순서)의 순서대로 만든다. U0·U1을 만들었다([U0·U1 만든 것](#u0u1-만든-것-2026-11-22)). U2를 만들었다([U2 만든 것](#u2-만든-것-2026-11-22)). U3을 만들었다([U3 만든 것](#u3-만든-것-2026-11-22)). 만들 때마다 이 문서를 고친다.

## 1. 사람 말과 목표

사람 말(2026-11-22):

> "ui도 전체적으로 개편해보자. 이번 것도 스스로 전부 판단하지 말고 정보를 수집해서 진행하면 되고, 지금 가방 안에서 진행하는게 너무 많아. npc 대화나 스킬, 패시브 트리 등등 이런건 별도 ui를 띄우는게 좋을 것 같아. ui 디자인 또한 너무 단조로워. 이것도 스스로 판단하지 말고 여러 정보 수집해서 개선안 준비해봐"

목표는 셋이다.

1. **가방을 가방으로 되돌린다.** 가방에는 몸에 걸친 것과 들고 있는 것만 둔다. 대화, 스킬, 특성 트리, 기록, 작업대는 각자 화면을 띄운다.
2. **사람과 물건을 만나는 화면을 하나로 맞춘다.** 이야기 인물과 상인이 같은 대화 화면을 쓴다. 상점·부탁·선물은 대화에서 고른다.
3. **단조로움을 깬다.** 판의 위계, 화면마다 다른 머리, 아이콘, 움직임, 소리로 화면마다 성격이 보이게 한다.

지키는 것: IMGUI와 코드로 그리는 그림, PC와 휴대폰 둘 다(`Docs/Design.md` 기술 원칙 7), 웹 시험이 누르는 단추 이름. 게임 규칙(Core)은 건드리지 않는다. 화면을 바꿔도 호스트에 보내는 명령은 같다.

## 2. 지금 UI

2026-11-22, main 93f7dc6의 코드와 배포본(0.97.0, UI 코드는 같다)을 헤드리스 Chromium으로 찍은 사진 98장으로 봤다. PC 1280×720, 휴대폰 세로 390×844, 작은 가로 휴대폰 740×360. 아래 사진 이름은 그때 찍은 것이다(`pc-`, `phone-`, `phone-wide-small-`).

### 화면 목록

| 묶음 | 화면 | 지금 모양 |
|---|---|---|
| 시작 메뉴 | 첫 화면, 게임 시작, 함께 하기, 저장본, 설정, 키 바꾸기 | 가운데 상자 하나에 "라벨 + 넓은 단추"를 쌓는다. 가장 정돈된 화면이다 |
| HUD | 상태 상자, 목표 목록, 미니맵, 터치 [가방][나가기], 시간·장소 줄, 스킬 칸, 퀵슬롯, 획득 줄, 배너, 보스 막대, 월드 위 단추, 이름표 | 왼쪽 위 상태·목표, 오른쪽 위 미니맵, 아래 스킬·퀵슬롯. 장르에 익숙한 배치다 |
| 게임 중 창 | 가방, 이야기 대화, 웨이포인트 목록, 전체 지도 | 창을 겹쳐 띄우는 관리자가 없다. `GameRoot.DrawScreen`의 그리는 순서가 위아래를 정한다 |
| 전용 화면이 없는 것 | 상인, 상자, 모루, 기계·문·벽, 작업대 제작, 쓰러짐 | 상인부터 작업대까지는 가방 안이다. 쓰러짐은 HUD 한 줄이다 |

### 가방에 몰린 것

가방(`InventoryWindow.cs`, 2102줄) 한 창이 **13개 화면**을 품고 있다. 늘 있는 탭 6개(장비, 재료·제작, 스킬, 특성, 캐릭터, 일지), 상황 탭 2개(상자, 상인), 탭 안의 하위 탭 8개(일지 3, 상인 5)다. 게임 전체의 단추 116곳 가운데 **75곳(65%)**이 이 파일에 있다.

성격이 다른 화면이 한 창에 섞여 있다.

- 가방다운 것: 장비 칸, 소지품
- 성장: 클래스 고르기, 스킬 배우기·변형, 스킬 칸 순서, 클래스 바꾸기, 특성 트리 51점, 능력치, 생활 기술, 펫
- 만남: 상인 8명의 사기·팔기·선물·부탁·이야기·이사 권하기, 상자, 모루, 기계·문·벽, 작업대 제작(조합법 약 169개)
- 기록: 목표·이야기, 도감, 업적

### 가장 큰 문제

1. **가방이 너무 많은 일을 한다.** 위의 13개 화면이다. [재료·제작] 한 탭이 앞의 기계 줄, 재료 줄, 재료 격자, 공장 기록, 조합법 169개를 한 스크롤에 잇는다(`pc-bag-crafting`). [스킬] 한 탭은 다섯 가지 일을 하고, 2클래스면 단추가 30개 넘는다(`pc-bag-skills`).
2. **NPC를 만나는 길이 둘이다.** 이야기 인물은 머리 위 [○○와 말하기] → 화면 아래 대화 창이다(`pc-story-talk`). 상인은 월드에 단추가 없고 "가방에서 거래"라는 떠 있는 글만 있다(`pc-world-merchant`). 같은 부탁·이야기가 대화 창과 가방에 다른 모양으로 있다(`pc-bag-merchant-request`).
3. **특성 트리를 읽을 수도 누를 수도 없다.** 점마다 이름 첫 글자 한 자다(`pc-bag-passives`). 휴대폰에서는 점이 12~16점으로 줄어 손가락으로 못 누른다(`phone-bag-passives`). 그래서 아래 "지금 배울 수 있는 점" 목록으로 돌아서 간다.
4. **가로 휴대폰에서 가방을 쓸 수 없다.** 내용이 보이는 높이가 약 160점이다. 상인 탭은 머리 글만으로 차서 살 물건이 한 줄도 안 보인다(`phone-wide-small-bag-merchant-buy`).
5. **휴대폰 세로에서 목표 목록이 화면 위 40%를 덮는다.** 보스전에서는 보스를 가리고, 보스 막대가 플레이어 머리 위로 밀린다(`phone-boss-bar`).
6. **겹침 버그가 넷이다.** "획득: …" 줄이 가방 위에 그려진다(`phone-bag-gear`). 가로 휴대폰에서 획득 줄이 목표 목록과 섞인다(`phone-wide-small-hud-field`). 구르기 칸 설명이 퀵슬롯 뒤에 깔린다(`pc-boss-bar`). 월드 위 단추 둘이 같은 자리에 겹친다(`phone-world-machine-switch`).
7. **틀과 단추가 한 종류라 위계가 없다.** 사람이 말한 "단조로움"의 원인이다. 가방, HUD 상자, 설명 상자, 대화, 지도가 모두 같은 금테 갈색 판(`UiArt.Panel`)이다. 단추도 하나다. 제목 띠, 닫기 단추, 탭 아이콘, 초상, 하트, 진행 막대, 구분선이 없다. 정보 대부분이 "·"로 이은 문단 글이다. 열고 닫을 때 움직임이 없다.
8. **전용 화면이 없는 순간이 있다.** 쓰러짐은 HUD 한 줄이다(`pc-death`). 휴대폰 전체 지도는 화면 1/3만 쓰고 범례가 잘린다(`phone-map-full`). 웨이포인트는 지도 대신 이름 목록이다(`pc-waypoints`).
9. **손가락 단추가 작다.** 월드 위 단추 26~28점, 대화 [다음] 30점, 가방 줄 단추 22~24점이다. 원칙 7은 40점이다.
10. **PC에서 쓸모없는 상자가 늘 떠 있다.** 가방 왼쪽의 "이름이나 칸에 마우스를 올리면 설명이 보입니다." 상자다(`pc-bag-skills`).

### 기술 제약

- **IMGUI만 쓴다.** `OnGUI`와 `GUI`/`GUILayout`. 씬·프리팹은 클라우드가 못 만들고, 손으로 만드는 콘텐츠를 늘리지 않는다. 새 화면도 코드로 그린다. IMGUI는 먼저 그린 컨트롤이 누르기를 가져가므로 창 아래의 단추는 그리지 않아야 한다.
- **크기는 `Ui`의 점 단위.** 꼭 들어가야 하는 화면: 휴대폰 세로 390×844(작은 것 360×640), 가로 844×390·740×360·667×375, 작은 PC 800×600, PC 1280×720, 태블릿 1024×768. 높이 480 미만은 `Ui.Short`다. `LayoutTests`가 7가지 크기에서 고정 요소가 화면 안에 있고 서로 겹치지 않는지 본다.
- **손가락 단추 40점 이상.** 마우스 올리기 설명은 터치에서 누르고 있기로도 본다.
- **단추는 `Ui.Button`·`Ui.LayoutButton`·`Ui.Toolbar`로.** 웹 시험이 단추 이름과 줄 이름으로 찾아 진짜 클릭·탭으로 누른다. 아이콘 칸은 `Ui.Probe`, 줄 글은 `Ui.Row`(가방은 `Fit`), 라벨은 `Ui.Wrap`을 거친다.
- **그림은 `Client/Art/`의 코드.** 틀은 `UiArt`의 작은 도트를 2배로 키운 9-slice다. 외부 PNG나 글꼴 파일을 넣으면 `.meta`와 임포트 설정이 필요해 로컬 일이 생긴다.
- **글꼴은 Galmuri11 Bold 하나, 12의 정수 배로만.** 12 아니면 24다. 크기로 위계를 만들기 어렵다. 색, 띠, 아이콘, 여백으로 만든다.
- **협동이라 창을 열어도 게임은 돈다.** 지금 가방이 열리면 스킬·퀵슬롯·월드 단추를 감추고 공격을 막는다(`Controls.Block`). 새 창도 같은 규칙을 따른다.
- **웹 빌드.** 에디터 전용 API를 못 쓴다(`UNITY_WEBGL` 컴파일 확인).
- **지금 키.** Q·E·R·F 스킬, C 물약, Tab 가방(I도 연다), M 지도, G 기계 켜기/끄기·상자 열기, LShift 구르기, 1~6 퀵슬롯. **C와 E는 이미 쓰고 있다.**

## 3. 찾아본 자료

다른 게임의 UI, 디자인 글, 모바일 기준, Unity 문서를 찾아봤다. 많이 쓴 것만 남겼다. 번호는 맨 아래 [자료 목록](#자료-목록)이다. 몇 곳은 자동 접속을 막아 2차 자료로 대신했다(목록에 적었다).

**비슷한 게임은 화면을 어떻게 나누나**

- Core Keeper는 스킬을 가방 안 별 모양 탭에 둔다[1]. 상인과 작업대는 따로 연다[2]. 우리가 지금 따르는 구조이고, 사람은 이것을 "너무 많다"고 봤다.
- Stardew Valley는 한 메뉴에 탭이 있지만 상점은 탭이 아니다. 상인 얼굴과 한 줄 대사가 붙은 따로 뜨는 화면이다. 편지, 달력, 게시판도 각자 화면이다[3]. 모바일은 세 줄 단추로 같은 메뉴를 연다[4].
- Terraria는 NPC 대화 창의 선택지 "Shop"을 누르면 상점이 열린다. 호감(Happiness)도 대화 창의 선택지다[5].
- Diablo IV는 소지품(캐릭터·장비·능력치), 스킬 트리, 파라곤 판, 지도, 일지가 다 따로다. 협동을 위해 성장 화면을 따로 또는 같이 열 수 있게 했다[6][7]. 2026년 스킬 트리 개편은 "누르고 써 보고 자라는 걸 보라", "바뀐 게 바로 보여야 한다"를 내세웠다[8].
- Path of Exile은 패시브 트리를 전체 화면으로 연다. 휠로 확대하고 끌어서 옮긴다. 검색창에 글자를 치면 맞는 점이 빛난다[10].
- Last Epoch은 퀘스트 창을 지도 창에 합쳤다("어느 지역 퀘스트인지 알게"). 패시브 창을 "덜 비좁게" 다시 짰다[11]. 설명 상자는 "설명(초보용) + 수치(훑어보기용)" 두 단이다[12].
- Hades는 화면이 세계의 물건에 붙어 있다. 거울은 영구 강화, 우물은 상점, 대화는 큰 초상과 이름이다[13].
- Factorio는 고른 탭이 판의 제목처럼 보인다. 칸은 어둡게 해서 아이콘을 띄운다. 닫기 단추를 늘 같은 자리에 둔다[14]. 마무리 때 UI 소리를 따로 만들어 단추의 손맛을 줬다[15].
- Genshin Impact와 Diablo Immortal은 허브 메뉴 하나에서 기능별 전체 화면으로 간다[16][9]. Diablo Immortal은 PC로 옮기며 메뉴는 그대로 두고 모든 기능에 단축키를 붙였다[9]. Torchlight Infinite는 모바일 메뉴를 PC에 그대로 써서 "마우스 올림 정보가 없다"는 불만을 들었다[18].

정리하면 이렇다.

1. 사람·물건과 만나서 여는 화면(대화, 상점, 작업대, 기계)은 따로 띄우고, 누구·무엇인지 보여 주는 머리를 붙인다[2][3][5][13][14].
2. 캐릭터를 키우는 큰 화면(스킬, 패시브 트리)도 따로다. 트리는 전체 화면, 확대·이동, 검색 강조가 표준이다[7][8][10].
3. 가방에는 몸에 걸친 것과 들고 있는 것이 남는다[7].
4. 일지는 지도 쪽으로 붙는다[7][11].
5. 단축키는 한 글자. 모바일은 허브 단추 하나 → 목적지 화면이다[31][9][16].

**단조롭지 않은 디자인**

- 층마다 밝기를 다르게 한다. 바닥 판, 안쪽 칸, 떠 있는 설명 상자가 서로 달라야 위계가 보인다. 1단 탭은 옆, 2단 탭은 위에 두거나 모양으로 나눈다. 열 때는 부모가 먼저, 자식이 나중이다[19].
- 창은 "판"과 "대화"로 나눈다. 판은 HUD와 함께 떠 있고, 대화는 화면 대부분을 차지하는 주 초점이다[20].
- 일관된 규칙 하나와 의도된 일탈 하나. Beastieball은 모든 UI가 한 기울기와 몇 가지 팔레트 번호만 쓴다. 대신 특별한 화면 하나는 일부러 전혀 다르게 해서 가장 사랑받았다. 열기·닫기는 `pos += (target - pos) * 0.3` 같은 보간 하나로 했다[21].
- 정보가 많은 RPG에서 지나친 미니멀은 답답하다. 바꾸기 위해 바꾸지 말라[17].
- 단추는 평소·초점·올림·눌림 네 상태. 한 화면에 주 동작 하나를 눈에 띄게 한다. 흐린(비활성) 단추보다 이유를 보여 주는 편이 낫다[22].
- 비교 설명은 착용 장비와 나란히, 얻는 것 초록·잃는 것 빨강. Diablo IV는 이것이 기본으로 꺼져 있어 "숨은 최고 설정"이라 불린다[23].
- 접근성: 글자 크기, 움직임 줄이기, 색 구분을 설정으로[24][31].

**대화 화면**

- 이름표, 초상, 본문, 넘김 표시 네 가지. 상자는 화면 아래, 짧은 대사면 화면의 15~20%, 많아도 30~35%[25].
- 초상은 본문 왼쪽, 표정 4~8개. 이름표는 상자 위에 걸친 띠, 인물마다 색[25].
- 타자 효과는 글자당 30~50ms, 문장부호 뒤 150~300ms 쉼. 첫 입력은 문장을 끝까지 보여 주고, 둘째 입력이 다음 줄이다[25][26].
- 선택지는 대사가 다 나온 뒤 2~4개, 결과 아이콘(하트=호감)을 붙인다[25][26]. Stardew 모드들은 이름표 옆에 호감 하트와 이번 주 선물 수를 붙인다[27].
- Eastward는 대사가 너무 많다는 비판을 들었다[28]. 대사는 짧게, 선택지로 빨리 본론(상점, 부탁)에 간다.

**모바일**

- 자주 누르는 조작 44×44pt 이상, 덜 중요한 메뉴 조작 28×28pt 이상[31]. Android는 48×48dp[32]. 우리 원칙 7의 40점은 그 사이다.
- 자주 쓰는 단추는 엄지 근처, 메뉴 같은 보조 조작은 화면 위. 이동·공격 영역은 비운다[31].
- 좁은 세로 화면은 아래에서 올라오는 시트와 아래 막대, 가로는 옆 판과 옆 레일[33].
- `Screen.safeArea`는 원점이 왼쪽 아래라 IMGUI에서는 y를 뒤집어야 한다[34].
- Dead Cells 모바일은 HUD를 가상 단추 자리에서 치웠다[35].

**손맛과 구현**

- 열기 0.12~0.18초, 살짝 넘쳤다 돌아오는 보간(easeOutBack)과 투명도. 단추는 누를 때 0.95배, 뗄 때 튀며 1배. 숫자가 바뀌면 잠깐 커졌다 돌아온다[29][30].
- `GUIUtility.ScaleAroundPivot`은 `GUI.matrix`를 바꾸는 전역 상태라 그린 뒤 되돌린다. 우리는 이미 `GUI.matrix`로 `Ui.Scale`을 쓰므로 "저장 → 곱하기 → 되돌리기"로 쓴다[36].
- 소수 배율로 키우면 픽셀이 울퉁불퉁해진다. 틀은 기기 픽셀의 정수 배로 맞춘다[37].
- Galmuri는 14(15px), 11(12px), 9(10px) 크기가 있다. 제목 14, 본문 11, 작은 수치 9를 쓰면 글자 크기로도 위계가 생긴다[38]. 다만 글꼴 파일을 더하면 로컬 일이 생긴다.

## 4. 개선안

### 4-1. 화면 나누기

가방 한 창을 **네 종류의 화면**으로 나눈다. 가방, 성장, 기록, 만남이다.

| 종류 | 화면 | 담는 것 | PC | 터치 | 형태 | 자료 |
|---|---|---|---|---|---|---|
| 가방 | 가방 | 착용 인형(주인공 그림 + 6칸), 소지품 격자와 분류(전체·장비·재료·소모품·룬), 고른 것의 설명·비교·동작, 핵심 능력치 한 줄, [손 제작] 작은 탭(작업대 없이 되는 것만) | Tab, I | [가방] | 옆 판(세계가 보인다) | [3][7] |
| 성장 | 스킬 | 클래스 고르기, 스킬 카드, 배우기·올리기·변형, 스킬 칸 배치 | K | 허브 → 스킬 | 전체 화면, 위에 성장 탭 셋 | [7][8] |
| 성장 | 특성 | 51점 트리, 확대·이동·검색, 고른 점 설명, 되돌리기 | P | 허브 → 특성 | 전체 화면 | [10][11] |

| 기록 | 도감·업적 | 몬스터·물고기·작물·장비 그림 칸(모르는 것은 실루엣), 업적 진행 막대 | J 뒤 탭 | 기록 탭 | 전체 화면 | [3] |
| 만남 | 대화 | 초상, 이름표, 호감 하트, 대사, 선택지 | 다가가서 G 또는 단추 | [○○와 말하기] | 화면 아래 대화 상자 | [5][25] |

나누는 규칙:

- **한 번에 큰 화면은 하나다.** 가방이 열려 있을 때 K를 누르면 가방이 닫히고 스킬이 열린다. 상자·상점·작업대처럼 "내 가방이 함께 필요한 화면"은 그 화면 안에 가방 판을 같이 그린다. 창을 둘 띄우지 않는다.
- **대화는 다른 화면 위에 남지 않는다.** 대화에서 [거래]를 누르면 대화 상자가 상점 머리(초상과 이름)로 줄어든다. 상점을 닫으면 대화로 돌아간다(Esc 한 번에 한 단계 뒤로).
- **문·금 간 벽은 화면을 만들지 않는다.** 지금 [재료·제작] 맨 위의 [고치기], [문 잠그기]/[잠금 풀기]는 월드 위 단추로 옮긴다.
- **재료는 소지품의 분류다.** 지금 "줄"과 "격자" 두 모양으로 그리는 재료를 격자 하나로 합친다. [놓기]·[심기] 같은 동작은 고른 것의 판에 나온다.
- **장비 칸은 한 곳에만.** 지금 [장비] 탭의 한 줄 착용 칸과 [캐릭터] 탭의 인형이 겹친다. 가방의 인형 하나로 합친다. 캐릭터 화면은 장비를 보여 주기만 한다.
- **허브(터치).** 미니맵 아래 [가방][나가기]를 [가방][메뉴]로 바꾼다. [메뉴]는 큰 아이콘 격자(가방, 스킬, 특성, 캐릭터, 일지, 지도, 설정, 나가기)를 연다. 포인트가 남으면 [메뉴]와 해당 아이콘에 금색 점을 단다. PC에서는 Esc 메뉴에 같은 격자를 두고, 단축키가 주 경로다[9][16].
- **G를 "만나기" 키로 넓힌다.** 지금 G는 기계 켜기/끄기와 상자 열기다. 말하기, 작업대·모루 열기도 G로 한다. 기계를 끄는 것은 기계 판의 단추로 옮긴다. E는 스킬 2라 쓰지 않는다.

### 4-2. 대화 화면

이야기 인물과 상인 8명이 같은 대화 화면을 쓴다.

**들어가기.** 모든 인물 머리 위에 [○○와 말하기] 단추를 단다(상인도). 지금의 "가방에서 거래" 떠 있는 글은 없앤다. 단추는 높이 40점이다. 둘 이상이 가까우면 겹치지 않게 세로로 쌓는다.

**모양.**

- 화면 아래, 높이는 화면의 30% 이하(세로 휴대폰은 35%)[25]. 스킬 칸·퀵슬롯은 대화 동안 감춘다. 지금은 퀵슬롯 위를 덮는다(`phone-story-talk`).
- 왼쪽에 초상. 지금 `PeopleArt`의 인물 그림을 정수 배로 키워 쓴다. 표정을 새로 그릴지는 [6절](#6-사람이-정할-것)에서 정한다.
- 상자 위에 걸친 이름표 띠. 인물마다 색이 다르다. 상인이면 띠 옆에 호감 하트 5칸(지금 "호감 0/5 (0/500)" 글 대신)과 금화를 둔다[27].
- 본문은 타자 효과. 글자당 35ms, 문장부호 뒤 200ms 쉼. 첫 탭은 문장을 끝까지, 둘째 탭이 [다음]이다[25][26]. 다 나오면 오른쪽 아래에 넘김 화살표가 통통 뛴다. 설정 "글 속도: 보통/빠름/즉시"를 둔다.
- 대화 중에는 HUD 목표 목록을 흐리게 한다. 가로 휴대폰에서 대화 상자가 목표 목록을 반쯤 덮는 문제(`phone-wide-small-story-talk`)가 없어진다.

**선택지.** 대사가 다 나온 뒤 아래에서 올라온다. 아이콘 + 글, 높이 40점 이상, 세로 목록이다. 상인이면 다음과 같다.

| 선택지 | 하는 일 | 지금 있던 곳 |
|---|---|---|
| [말 걸기] | 오늘의 말, 호감 이야기 | 상인 탭 머리 |
| [거래] | 상점 화면(사기·팔기) | 상인 탭의 [사기]·[팔기] |
| [선물] | 건넬 것 고르기, 이번 주 선물 수 | 상인 탭의 [선물] |
| [부탁] | 필요한 것, 보답, [건네기]/[아직 모자라다] | 상인 탭의 [부탁] |
| [이야기] | 호감 이야기 | 상인 탭의 [이야기] |
| [이사 권하기] | 이사 조건과 단추 | 상인 탭 머리 |
| [닫기] | 대화 끝 | – |

잠긴 선택지는 흐리게 감추지 않고 자물쇠 아이콘과 이유("호감 2부터")를 보인다[22]. 이야기 인물은 지금처럼 이야기 줄과 고를 답을 쓰고, 부탁이 있으면 [부탁]이 붙는다.

**상점.** 대화 상자가 위로 줄어 초상과 이름표만 남는다. 아래는 두 판이다. 왼쪽(세로 휴대폰은 위) 상인 물건, 오른쪽(아래) 내 가방이다. 위에 [사기][팔기] 탭이 있다. 물건을 고르면 아래 고정 줄에 값, 산 뒤 남는 금화, 지금 낀 것과 비교가 나온다. 잠긴 물건은 목록 맨 아래에 모은다. 지금처럼 "아이콘 이름 · 금화 N [사기][×5]" 줄 20개를 그대로 쌓지 않는다(`pc-bag-merchant-buy`).

### 4-3. 특성 트리와 스킬 화면

사람이 따로 띄우자고 한 대표 화면이다. 둘 다 전체 화면이고, 위에 [스킬][특성][캐릭터] 탭이 있다. PC는 K·P와 탭, 패드처럼 Q/E로 옆 화면에 가는 것은 하지 않는다(Q·E가 스킬 키다).

**특성 트리.**

- 배경을 별하늘로 깐다. 이 화면 하나는 다른 화면과 일부러 다르게 한다[21].
- 점마다 아이콘과 색이다. 공격 빨강, 방어 초록, 마법 파랑, 그 밖 금색. 색은 그 점이 올리는 능력치(`passives.csv`의 `stats`)에서 Client가 정한다. 시트는 바꾸지 않는다. 큰 점(notable)은 작은 점의 두 배다. 배운 점은 빛나고, 배울 수 있는 점은 테두리가 숨쉬듯 깜박이고, 못 배우는 점은 어둡다.
- 확대·이동. PC는 휠과 끌기, 터치는 두 손가락 벌리기와 한 손가락 끌기[10]. 확대하면 점 아래에 이름이 나온다. 터치에서 점은 늘 40점 이상으로 눌린다(그만큼 확대된 채로 연다).
- 검색. 위쪽 입력칸에 글자를 치면 맞는 점이 빛난다[10].
- 고른 점의 설명은 화면 오른쪽(세로 휴대폰은 아래) 고정 판이다. 트리를 밀지 않는다. 판에 [배우기]가 있다. 설명은 두 단이다. 위는 한 줄 설명, 아래는 수치다[12].
- "지금 배울 수 있는 점" 목록은 판 아래 접는 서랍으로 남긴다. 시험도 이 목록으로 누른다.
- 배우면 점이 번쩍하고 이어진 선을 따라 빛이 흐른다. 소리는 `Sound.Learn`[8].
- [모두 되돌리기 (금화 5)]는 화면 구석에 위험 동작 모양(붉은 테)으로 둔다.

**스킬.**

- 맨 위에 스킬 칸 줄. 실제 스킬 칸(`SkillBar`)과 같은 큰 아이콘, 같은 키 글자다. 칸을 누르고 아래 스킬을 누르면 바뀐다(지금의 ▲▼[바꾸기] 대신. [바꾸기]는 이름을 남겨 둔다).
- 그 아래 클래스마다 한 열, 스킬 카드 6장. 카드는 큰 아이콘(정수 배), 이름, 단계 점(●●○○○), 태그 색 띠다. 숫자 설명은 카드를 고르면 옆 판에 나온다.
- 옆 판에 [배우기]/[올리기], [변형](결정 끼우기·빼기), 숫자 설명, 다음 단계 비교.
- 스킬 포인트와 [되돌리기 (금화 20)]는 위 오른쪽.
- **클래스 고르기**는 빈 칸이 있을 때 스킬 화면 대신 먼저 뜬다. 클래스 카드 다섯 장이다. 그 클래스 무기를 든 주인공 그림(`HeroArt`), 클래스 색, 대표 스킬 세 개, [고르기][미리보기]다. 줄 글 "전사: …" 형식은 시험이 읽으므로 남긴다.
- **클래스 바꾸기**(작업대 곁에서만)는 스킬 화면 맨 아래가 아니라 작업대 화면의 단추로 옮긴다. 들어가면 같은 카드 화면을 쓴다.

**캐릭터.** 가운데 큰 주인공 그림(지금 낀 장비 그대로), 양옆에 능력치 표(아이콘 + 이름 + 값, 두 열). "생명력 192 · 재생 0/초 · …" 문단을 없앤다. 아래에 생활 기술 4가지와 혜택, 펫.

**추천: A를 바탕으로, 화면 종류마다 B의 머리와 바닥 무늬만 바꾼다.**

- 공통 규칙(A): 테 두께, 단추 모양, 글자, 희귀도 색, 움직임은 모든 화면이 같다. 색은 번호 팔레트 하나에서 꺼낸다[21].
- 화면 종류의 표시(B): 제목 띠의 재질과 아이콘, 판 안쪽의 옅은 무늬만 다르다. 가방은 가죽, 성장은 룬 돌, 기록은 양피지, 만남은 나무(상점)·쇠(기계·모루).
- 특성 트리 하나만 일부러 가장 다르게(별하늘 전체 화면)[21].

어느 안이든 함께 하는 것:

- **판 위계 3단.** 바닥 판(어두움) → 안쪽 칸(더 어두움, 아이콘이 뜬다[14]) → 떠 있는 설명 상자(밝음)[19].
- **단추 세 가지.** 주 동작(금색, 한 화면에 하나), 보조 동작(지금 단추), 위험 동작(붉은 테: 버리기, 지우기, 되돌리기)[22]. 지금 [버리기]가 [장착] 바로 옆에 같은 모양으로 있다(`pc-bag-gear-picked`).
- **창 머리.** 제목 띠, 아이콘, 오른쪽 위 [닫기](늘 같은 자리)[14]. 지금의 "가방 (Tab 또는 I로 닫기)" 글을 대신한다.
- **탭 두 단.** 1단(화면 종류 안의 화면)은 아이콘 + 짧은 이름의 큰 탭, 2단(분류)은 작은 글 탭이다[19].
- **아이콘을 더 그린다.** 탭, 능력치, 금화, 하트, 자물쇠, 닫기, 체크. 16px 도트로 `Art/`에 그린다.
- **글자 위계.** 글꼴은 그대로 두고 색, 띠, 아이콘, 여백으로 만든다. 제목용 Galmuri14를 더할지는 시안을 보고 정한다(로컬 일이 생긴다)[38].
- **틀은 기기 픽셀 정수 배.** `Ui.Scale`이 소수(예 2.625)여도 틀의 픽셀은 고르게[37].
- **비교는 기본으로 켠다.** 고른 장비 판에 지금 낀 것과의 차이를 초록·빨강으로[23].

### 4-5. 휴대폰 배치 규칙

1. **단추 크기.** 자주 누르는 것 44점, 목록 줄과 탭도 40점 이상(원칙 7). 터치에서는 줄이 길어지니 한 화면의 줄 수가 준다. 그래서 목록 + 고른 것의 판으로 나눈다[31][32].
2. **세로 화면(좁음).** 옆 판으로 여는 화면(가방, 상자, 작업대, 상점)은 아래에서 올라오는 시트다. 화면 높이의 60~90%. 탭은 시트 위 끝의 아이콘 줄이다[33].
3. **가로 화면(`Ui.Short`).** 옆 판은 오른쪽에서 나온다. 탭은 판 왼쪽의 세로 레일이다. 머리 글을 한 줄로 줄여 내용 높이를 지금(약 160점)의 두 배 가까이로 늘린다. 목표 목록과 상태 상자는 창이 열린 동안 그리지 않는다[33].
4. **전체 화면.** 성장·기록은 어느 크기에서나 전체 화면이다. 뒤의 세계는 어둡게 비친다(얼마나 비칠지는 6절).
5. **닫기.** 오른쪽 위 [닫기]가 늘 같은 자리. 옆 판은 바깥 어두운 곳을 눌러도 닫힌다[14][33].
6. **허브.** [가방][메뉴] 두 단추만 화면 위에 둔다. 메뉴 같은 보조 조작은 위가 맞다[31].
7. **안전 영역.** 모든 화면을 `Screen.safeArea` 안에 둔다(y 뒤집기)[34].
8. **길게 누르기.** 마우스 올림 설명은 터치에서 길게 누르기 → 설명 시트다. PC에서 늘 떠 있던 "마우스를 올리면…" 상자는 없앤다[18].
9. **이동 영역.** 싸우는 중에 여는 창(가방, 대화)은 왼쪽 아래 이동 영역을 덮지 않는다[31][35].
10. **목표 목록.** 세로 휴대폰에서는 한 줄(지금 큰 목표)로 접고, 누르면 일지가 열린다. 보스전에서는 저절로 접는다.

### 4-7. 지켜야 할 것

웹 시험(`sweep.js`, `playtest.js`, `bot.js`, `feel.js`)과 PlayMode 시험이 지금 UI에 기대고 있다. 화면을 옮겨도 이것들이 계속 돌아야 한다.

**단추 이름은 그대로 둔다.** 사기, 팔기, 만들기, 놓기, 넣기, 심기, 배우기, 올리기, 고르기, 장착, 다듬기, 건네기, 이사 권하기, 부탁, 이야기, 선물, 말 걸기, 다음, 알겠다, 닫기, 지도, 지도 닫기, 가방, 웨이포인트 등이다. 정규식으로 찾는 이름(`강화 +1`, `모두 되돌리기 (금화 5)`, `되돌리기 (금화 20)`, `이대로 바꾸기`, `… 결정 끼우기`, `공장 생산 보기`, `고치기`, `○○와 말하기`)도 같은 글로 시작하게 둔다. 설정 단추는 "이름: 값" 형식을 지킨다. 새 단추([거래], [메뉴], 새 설정)는 새 이름이다.

**줄 글 형식을 지킨다.** "이름 ×개수", "클래스명: 설명", 조합법 이름이 줄 첫머리. 줄 글은 `Ui.Row`로 적는다. 격자 칸은 `Ui.Probe`로 이름을 붙이고, 시험이 쓰는 줄 이름("소지품", "착용")을 남긴다.

**HUD 글.** 목표 목록을 접거나 아이콘으로 바꿔도 `GameRoot.DrawHud`가 모으는 줄(`_hudLines`)에는 지금 글이 그대로 들어간다. "쓰러졌습니다", "귀환 중", "스킬 포인트 N", "특성 포인트 N", "목표 N/M", "부탁: 상인 …", "이야기: 상인 …" 등이다. 쓰러짐 전용 화면을 만들어도 이 줄은 남긴다. "(가방에서)"는 새 경로에 맞게 바꾸되 "스킬 포인트 N" 부분은 그대로다.

**입구를 옮긴다.** 지금 `Playtest`의 `bag <탭 이름>`, `GameRoot.ShowBag(page)`, `BagOpen`, PlayMode의 `ShowBag("스킬")`·`ShowBag("재료·제작")`이 가방 탭 이름으로 연다.

- 새 명령 `screen <이름>`(가방, 스킬, 특성, 캐릭터, 일지, 도감, 업적, 지도, 대화, 상점, 상자, 작업대, 모루)을 만든다. `report`에 지금 열린 화면 이름(`screen`)을 더한다.
- 옛 이름은 한동안 번역해 받는다. `bag 스킬`은 스킬 화면, `bag 특성`은 특성 화면, `bag 상인`은 곁의 상인과 대화 → 상점, `bag 상자`는 상자 화면, `bag 재료·제작`은 곁에 작업대가 있으면 그 작업대 화면, 없으면 가방의 [손 제작]이다. `report.bag`은 "가방 종류의 화면이 열려 있나"로 남긴다.
- `sweep.js`의 `bagTab()` 도우미 하나를 새 입구로 바꾼다(32곳이 이것을 부른다). `layout` 구역의 탭 목록(`['장비', '재료·제작', '스킬', '특성', '캐릭터', '일지']`)을 새 화면 목록으로 바꾼다.

**타자 효과와 움직임.** 시험은 [다음]을 한 번 눌러 다음 줄로 간다고 본다. `Playtest`가 켜지면 글 속도를 "즉시"로, 움직임을 "줄이기"로 둔다. 사진을 찍기 전에 열기 움직임이 끝나 있어야 한다.

**배치 시험.** `LayoutTests`의 영역 함수(`Ui.HudArea`, `Ui.MinimapArea`, `Ui.InfoArea`, `Ui.TouchButtonArea`, `SkillBar.Area`, `Hotbar.Area`, `StoryScreen.ListArea`)에 새 고정 요소를 더한다. [메뉴] 단추, 대화 상자, 월드 위 단추 묶음이다. 7가지 크기에서 화면 안에 있고 겹치지 않는지 본다.

**그리는 순서.** 월드 위 단추 → HUD → 열린 화면 → 설명 상자 순으로 그린다. 화면이 열려 있으면 그 아래 단추는 그리지 않는다. 획득 줄과 배너는 화면 아래에 그린다. 새 화면마다 `Controls.Block`과 스킬 입력 막기를 한 곳(화면 관리자)에서 한다.

- **시험과 그림.** PlayMode `LayoutTests`에 `WorldButtonsNeverShareASpot`(일곱 크기에서 다섯 단추가 한 자리를 원해도 겹치지 않고 터치 40점)와 `TheBossBarKeepsClearOfThePlayer`(세로 휴대폰에서 목록이 접히고, 보스 막대가 화면 안·미니맵 칸 밖·플레이어 머리 위 30점 위)를 더했다. `sweep.js --only ui`(PC, 휴대폰 세로, 작은 가로 휴대폰, 화소비 2.625 휴대폰)와 `playtest.js`의 정수 배 확인을 더했다. 상태 보고에 `ui`(가방·획득 줄·보스 막대 자리, 왼쪽 열 아래, 접힘, 플레이어 자리, 배율과 `dots`, 움직임)를 더했다. `dotnet run --project DevTools/ArtPreview -- --only ui`가 `out/ui/skin.png`(조각 전부), `windows.png`(지금 화면에 입힌 모습), `pixels.png`(정수 배 틀)를 그린다. 전체 실행에도 들어 있다.

### 다르게 한 것

- **글자 크기 위계는 만들지 않았다.** 글꼴은 Galmuri11 하나(12의 정수 배)라 제목도 12다. 위계는 머리 띠·색·아이콘·여백으로 만든다. Galmuri14(제목)·Galmuri9(작은 수치)를 쓰려면 글꼴 파일과 임포트 설정이 필요해 로컬 일이 생긴다(4-4의 말대로 시안을 보고 정할 일로 남긴다).
- **창 안 내용의 0.03초 늦은 등장은 하지 않았다.** 판과 내용이 함께 커진다. 내용 중 `GUI.color`를 직접 정하는 곳(희미한 칸 등)은 열리는 0.15초 동안 투명도를 따르지 않는다.
- **닫기 움직임은 틀만이다.** IMGUI는 닫힌 창의 내용을 다시 그릴 수 없어서 판과 머리 띠만 0.08초 줄며 사라진다.
- **단추를 뗄 때 튀는 움직임(1.03배)은 하지 않았다.** 누름(0.95배, 1점 아래)과 올림만.
- **소리는 재질마다 다르지 않다.** 여섯 소리를 모든 창이 같이 쓴다(4-6의 "돌, 나무, 종이마다 조금씩"은 남은 일).
- **탭 바꾸기의 미끄러지는 표시는 없다.** 고른 탭이 금색으로 바로 바뀐다.
- **가방 머리 띠는 탭을 따른다.** 가방을 아직 나누지 않아서(U2+) 한 창이 탭에 따라 가죽·밤하늘·양피지·천막·쇠판으로 머리를 바꾼다. 나눈 뒤에는 화면마다 하나다.
- **닫기 단추의 시험 이름은 "창 닫기"다.** 시험이 이미 누르는 [닫기](대화 끝, 웨이포인트 목록 아래)와 겹치지 않게 했다. 웨이포인트 목록 아래의 [닫기]는 그대로 있다.
- **"마우스를 올리면 설명" 줄.** 가방 제목 줄("가방 (Tab 또는 I로 닫기)")을 머리 띠로 바꿨다. 옆에 설명 자리가 없을 때의 안내 줄은 낮은 가로 화면(`Ui.Short`)에서는 뺐다. PC의 떠 있는 안내 카드는 U6에서 없앤다.

### 남은 문제

- **Unity에서 아직 못 봤다.** 클라우드는 컴파일(에디터·웹)과 ArtPreview 그림만 확인했다. 실제 화면(틀이 기기 픽셀에 맞는지, 그룹·스크롤 안의 `Snap`, 열기 움직임 중 단추 자리)은 웹 배포 뒤 `sweep.js --only ui` 사진으로 본다. 열고 닫는 손맛, 단추 눌림, UI 소리 여섯은 사진으로 알 수 없어 사람에게 묻는다.
- **스크롤바와 글 입력칸은 아직 예전 스킨 텍스처다**(GUIStyle 배경). 소수 배율에서 그 테두리만 고르지 않을 수 있다.
- **고른 장비 판의 안쪽 칸은 한 프레임 늦게 따라온다.** IMGUI는 묶음의 크기를 그린 뒤에야 알아서, 지난번 자리에 우물을 먼저 그린다. 판 크기가 바뀌는 프레임에 한 번 어긋날 수 있다.
- **가로 휴대폰에서 가방 내용 높이가 약 10점 줄었다.** 머리 띠(약 34점)가 예전 제목 줄(약 24점)보다 높다. 낮은 화면에서는 띠 아래·창 아래 여백을 줄이고 안내 줄을 뺐지만 다 메우지 못했다. U2·U6에서 가로 화면의 옆 판·세로 탭 레일로 푼다.
- **월드 단추가 많이 쌓이면 화면 위로 나갈 수 있다.** 다섯 개까지는 시험했다. 실제로는 둘 셋이다.
- **작은 세로 휴대폰(360×640) 보스전에서 HUD가 쓰러짐 줄 여러 개를 그리면** 보스 막대가 다시 내려온다(협동에서 여럿이 쓰러진 때). 배치 시험은 막대·줄 하나를 기준으로 했다.
- **대화의 초상·타자 효과·선택지 아이콘, 상점 두 판, 화면 관리자, 터치 [메뉴] 허브는 U2~U3이다.** 머리 띠의 하트는 상인과 같은 이름의 인물일 때만 나온다(이야기 인물은 호감이 없다).

## U2 만든 것 (2026-11-22)

사람 말 "지금 가방 안에서 진행하는게 너무 많아. npc 대화나 스킬, 패시브 트리 등등 이런건 별도 ui를 띄우는게 좋을 것 같아"의 첫 걸음이다. 가방의 탭이던 화면을 각자 창으로 띄우고, 한 번에 하나만 여는 관리자, 단축키, 휴대폰 허브, G "만나기"를 만들었다. 창 안의 내용은 아직 옛 탭 그리기를 그대로 옮긴 것이다(U4·U5에서 다시 짠다).

### 만든 것

**화면 관리자(`Client/ScreenStack.cs`, 새 파일).** 열린 화면은 하나다(`GameScreen`).

| 화면 | 묶음 | PC | 터치 | 모양 | 머리 띠 |
|---|---|---|---|---|---|
| 가방(장비, 재료·제작, 곁에 있으면 상자·상인 탭) | 가방 | Tab, I | [가방], [메뉴] → 가방 | 옆 판(지금 자리). 세로 휴대폰은 미니맵 칸 아래 시트 | 가죽(상자는 쇠판, 상인은 천막과 하트) |
| 스킬 | 성장 | K | [메뉴] → 스킬 | 전체 화면, 위에 [스킬][특성][캐릭터] 탭 | 밤하늘 |
| 특성 | 성장 | P | [메뉴] → 특성 | 전체 화면, 창 안이 별하늘 | 밤하늘 |
| 캐릭터 | 성장 | U | [메뉴] → 캐릭터 | 전체 화면 | 밤하늘 |
| 일지(목표·이야기, 도감, 업적) | 기록 | J | [메뉴] → 일지, 접힌 목표 줄 | 전체 화면, 위에 [일지][지도] 탭 | 양피지 |
| 지도 | 기록 | M | [메뉴] → 지도, 미니맵 | 전체 화면, 위에 [일지][지도] 탭 | 양피지 |

- **여닫는 규칙.** 화면을 열면 열려 있던 화면, 허브, 이야기 대화, 웨이포인트 목록이 닫힌다. 같은 키를 다시 누르면 닫히고, 다른 화면의 키는 그 화면으로 바꾼다([스킬]이 열린 채 Tab이면 가방). 묶음 안에서는 탭으로 옮겨 간다(같은 창이라 열기 움직임이 다시 나오지 않는다). 머리 오른쪽 위 닫기 단추([창 닫기], 지도는 [지도 닫기]).
- **Esc는 한 단계 뒤로.** 허브 → 열린 화면 → 이야기 대화·웨이포인트 목록 → 아무것도 없으면 지금처럼 게임에서 나간다. 전에는 가방이나 대화가 열린 채 Esc를 누르면 바로 게임에서 나갔다.
- **입력 막기를 한 곳에서.** 전체 화면이 열린 동안 `GameRoot`는 그 밑의 HUD·월드 단추·스킬 칸·퀵슬롯을 그리지 않고(뒤의 세계를 70% 어둡게, 다치면 가장자리가 붉게), 걷기·공격·스킬·물약·퀵슬롯·G를 받지 않는다. 터치는 화면 전체를 막는다. 가방(옆 판)은 지금처럼 걸을 수 있고 공격·스킬만 막는다. 화면이 바뀔 때마다 IMGUI 키보드 초점을 놓는다(펫 이름 칸).
- **단축키.** 사람이 정한 대로 Tab·I 가방, K 스킬, P 특성, J 일지, M 지도, U 캐릭터, C는 물약 그대로. 키 바꾸기 목록에 "스킬 창", "특성 창", "일지", "캐릭터"가 생겼다(새 동작은 끝에 붙여 저장된 키가 그대로다). PC에서는 창 머리 제목에 키가 붙고("스킬 (K)", "가방 (Tab)"), 묶음 탭에 마우스를 올리면 키를 알리는 카드가 뜬다. HUD의 "스킬 포인트 N" 줄 끝은 "(가방에서)" 대신 PC는 "(K·P)", 휴대폰은 "([메뉴]에서)"다.
- **휴대폰 허브.** 미니맵 아래 [가방][나가기]를 [가방][메뉴]로 바꿨다. [메뉴]는 큰 단추 일곱(가방, 스킬, 특성, 캐릭터, 일지, 지도, 나가기, 92×44점, 아이콘 위에 이름)의 판을 미니맵 칸 아래에 연다. 세로는 두 열, 낮은 가로 화면은 세 열로 들어가는 만큼(`ScreenStack.HubLayout`). 단추를 누르면 그 화면이 열리고 허브는 닫힌다. 판 바깥을 누르거나 [메뉴]를 다시 누르면 닫힌다. 허브가 열린 동안 스킬 칸과 월드 단추는 그리지 않는다(겹친 탭이 스킬을 쓰지 않게). 스킬·특성 포인트가 남으면 [메뉴]와 허브의 [스킬]·[특성]에 금색 점. 휴대폰에서 성장·기록은 화면 전체를 덮는 시트다(가장자리 4점).
- **G "만나기".** 사람이 정한 대로 말하기와 작업대 열기까지 넓혔다. 한 번에 한 가지, 이 순서다(`GameRoot.NextMeeting`).
  1. 마주 본 기계 켜기·끄기. 겨누어 마주 선 것이라 먼저다. 기계 위 [끄기 (G)]·[켜기 (G)]는 그대로다.
  2. 곁의 이야기 인물과 말하기(단추 [○○와 말하기]와 같다).
  3. 곁의 상인 → 가방 [상인] 탭(U3에서 대화로 바뀐다). 상인 이름표의 "가방에서 거래"는 PC "거래 (G)", 휴대폰 "[가방]에서 거래"로.
  4. 열린 웨이포인트·길잡이 돌 → 목록.
  5. 상자·수레·제단·광차 역(볼거리), 6. 던전 문·나가는 문·던전 상자(전과 같은 순서).
  7. 곁의 상자 → 가방 [상자], 8. 모루 → 가방 [장비](다듬기), 9. 작업대·화로 → 가방 [재료·제작].
  PC에서는 G가 지금 할 그 대상의 월드 단추에만 "(G)"를 붙인다(사람이 기계를 마주 보면 [말하기]에는 붙지 않는다). 대화가 열린 동안 G는 대화를 다시 시작하지 않는다. 화면이 열려 있으면 G는 아무것도 하지 않는다.
- **특성의 별하늘.** `UiArt.StarField`(96×96 이어지는 밤하늘 조각, 별 세 가지 크기)를 [특성] 창 머리 아래에 깔았다(`UiSkin.Stars`). 트리 자체는 U4다.
- **그림.** `DevTools/ArtPreview -- --only ui`의 `out/ui/windows.png` 아래 줄에 성장(스킬, 별하늘의 특성)과 기록(일지, 지도) 창과 묶음 탭, 오른쪽 위에 세로 휴대폰의 [가방][메뉴]와 열린 허브를 그렸다. 위의 U1 가방은 [장비][재료·제작] 탭만 남겼다.
- **시험.** 명령 `screen <이름>|off|hub`, 상태 보고 `window`(열린 화면 이름)·`hub`·`meet`(G가 할 일)·`bagPage`·`talking`·`ui.window`. 옛 `bag <탭>`은 그 탭이 지금 있는 곳을 연다(`bag 스킬`은 스킬 화면, `bag 재료·제작`은 가방). `report.bag`은 "가방이던 화면(가방·성장·일지)이 열려 있나"이고 `bag off`는 그것을 닫는다. PlayMode `ShowBag("스킬")`·`BagOpen`도 그대로 돈다. PlayMode `LayoutTests.EveryScreenFits`(800×600, 375×812, 740×360과 일곱 크기에서 화면마다 화면 안·내용 자리·닫기 단추, 휴대폰 전체 시트, 가방이 미니맵 칸을 비키는지, 허브 단추 40점·화면 안·서로와 칸을 비키는지), `FeatureTests.EveryScreenDraws`(화면마다와 허브, 휴대폰 특성의 사진). `sweep.js --only screens`(위 규칙과 G를 PC에서, 허브를 휴대폰 둘에서), `playtest.js`에 K와 [메뉴] 허브 확인.

### 다르게 한 것

- **창 안 내용은 그대로다.** 스킬·특성·캐릭터·일지는 옛 탭 그리기를 넓은 창에 옮겼다. 창이 넓어(PC 760점) 특성 트리의 점 간격이 커졌다. 카드·트리·표는 U4·U5다.
- **가방 화면에 상자·상인 탭이 남았다.** 4-1은 만남 화면으로 떼어 내지만 U3의 일이다. G가 상자·상인·작업대 곁에서 그 탭으로 연다.
- **기계를 끄는 것은 G에 남겼다.** 4-1은 기계 판의 단추로 옮기자고 했지만, 기계 판(U3)이 아직 없고 [끄기 (G)]를 지키라는 요청대로 G의 첫 순서로 두었다.
- **가방은 휴대폰에서 전체 시트가 아니다.** 4-5의 "옆 판은 아래에서 올라오는 시트(60~90%)"대로 미니맵 칸 아래에 둬서 [가방]·[메뉴]가 늘 보인다(세로 390×844에서 높이의 약 76%). 성장·기록은 어느 크기에서나 전체 화면이다.
- **허브에 설정이 없다.** 게임 안 설정 화면이 아직 없다. [나가기]는 허브 안으로 들어갔다. PC의 Esc 메뉴 격자(4-1 허브)도 아직 없다. PC는 단축키가 주 경로다.
- **지도는 판 바깥을 눌러야 닫힌다.** U1까지는 지도 어디를 눌러도 닫혔다. 지도 창이 기록 묶음의 크기(PC 760점)가 되고 탭이 생겨, 창 안을 누르면 닫히지 않고 창 바깥(넓은 화면의 양옆)이나 닫기 단추로 닫는다.

### 남은 문제

- **Unity에서 아직 못 봤다.** 컴파일(에디터·웹)과 ArtPreview 그림만 확인했다. 전체 화면의 실제 모습, 허브의 자리, 탭 전환, 키 막기는 배포 뒤 `sweep.js --only screens`·`layout`·`touch`·`ui`의 사진으로 본다. 열고 닫는 손맛, G의 순서가 자연스러운지는 사람에게 묻는다.
- **전체 화면 중에 쓰러지면** [집에서 일어나기]·쓰러짐 줄이 화면 밑에 가려 화면을 닫아야 보인다. 붉은 가장자리만 보인다(U7의 쓰러짐 화면에서 푼다).

- **`Docs/Classes.md` 등 옛 문서의 "가방 [스킬] 탭" 말은 고치지 않았다.** 게임 안 글(목표 안내, 메뉴의 클래스 안내, 레벨업 알림)은 새 경로로 고쳤다.

- **가방 [재료·제작]은 모든 조합법을 그대로 보인다.** 작업대 창은 그 작업대의 조합법만 보이는 새 입구이고, 가방의 목록은 시험 30여 곳(농사·공장·생활·기초)이 기대고 있어 U6(가방 정리)에서 손 제작만 남긴다. `bag 재료·제작`도 그대로 가방이다(4-7의 "곁에 작업대가 있으면 작업대 화면"은 하지 않았다).
- **기계 판은 만들지 않았다.** 지금 기계에는 따로 여는 화면이 없고, 거름망·생산 기계·우리·통발·발전기의 단추는 가방 [재료·제작] 맨 위에 마주 본 기계의 줄로 남아 있다. 문 잠그기·고치기도 그곳이다(월드 단추로 옮기는 것은 남은 일).
- **휴대폰의 만남 창은 시트다.** 4-5의 "옆 판은 아래에서 올라오는 시트(60~90%)"보다 크게, 화면 전체를 덮는다. 두 판을 넣을 자리가 그만큼 필요했다. 그동안은 걷지 못한다.
- **상점 판의 가방 칸은 보기만 한다.** 칸을 눌러 팔기는 하지 않았다(파는 것은 [팔기] 탭의 카드). 고른 것의 값·비교를 보이는 아래 고정 줄도 없다.
- **보고의 `typing`은 펫 이름 칸의 것이라** 대사가 찍히는 중은 `talkTyping`으로 따로 두었다.

### 남은 문제

- **Unity에서 아직 못 봤다.** 컴파일(에디터·웹), Core 시험, ArtPreview 그림만 확인했다. 실제 초상의 정수 배(휴대폰 화소비 2.625에서 2점은 5픽셀), 카드의 글이 잘리는지, 두 판의 스크롤과 손가락 끌기, 휴대폰 시트, G·Space·Enter 넘기기는 배포 뒤 `sweep.js --only encounter`(그리고 바꾼 확인이 있는 `basics`, `npc`, `gear`, `screens`, `travel`)의 사진으로 본다. 타자 효과의 빠르기, 표정이 대사에 맞는지, 사고파는 손맛은 사람에게 묻는다.
- **표정은 낱말로 고른다.** 낱말 목록이 짧아 틀린 표정이 나올 수 있다("미안"이 들어간 농담 등). 맞지 않는 줄이 많으면 `story.csv`에 표정 표시를 더하는 것(Core의 줄 형식 변경)을 생각한다.
- **카드의 이름이 길면 잘린다.** 세로 휴대폰에서 이름 칸이 약 130점(한글 10자 남짓)이다. 설명 카드(누르고 있기)에 다 나온다.
- **답이 셋인 낮은 화면의 대화는 높다.** 740×360에서 화면의 절반 가까이(답 두 열). 왼쪽 위 HUD·목표 목록 아래쪽을 덮을 수 있다(대화가 위에 그려진다).
- **PC의 만남 창은 HUD 상자 위를 덮는다.** 창이 미니맵 칸 왼쪽 가운데에 놓여 1280×720에서 왼쪽 위 HUD(막대만 그린다)를 가린다. 생명력은 붉은 가장자리로만 알 수 있다.
- **만남 창 사이의 이동이 없다.** 작업대 창에서 바로 상자 창으로 가는 탭은 없다(곁에 둘 다 있으면 닫고 다른 단추로).
